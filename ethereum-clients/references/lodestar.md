# Lodestar (consensus)

TypeScript (Node ^24, pnpm + lerna monorepo; some Zig native bindings in `src/` + `bindings/` for `@lodestar/native`). GitHub: https://github.com/ChainSafe/lodestar. Local: `~/Projects/ethereum/lodestar`, default branch `unstable` (`stable` tracks releases; PRs target `unstable`).
Latest release: `git tag --sort=-v:refname | grep -v rc | head` (tags `v1.x.y`, rc tags `-rc.N`). At time of writing: `v1.50.1`; `lerna.json` `version` shows the version of the checkout. Verified against `unstable` @ 14a10bec6 (Nov 2026), which is already post-Gloas/Heze aware (ePBS, builders in VC, inclusion lists).

## 1. Orientation

Packages (`packages/*`): `beacon-node` (chain, network, sync, db, execution, REST impl), `api` (route defs + client + server registration, shared), `validator` (VC lib), `cli` (yargs; `lodestar beacon|validator|dev|bootnode|lightclient...`), `state-transition`, `fork-choice`, `config` (chain config + per-network configs in `src/chainConfig/{configs,networks}`), `params` (presets/forks), `types` (SSZ types), `db`, `reqresp`, `era`, `builder`, `logger`, `utils`, `test-utils`, `spec-test-util`. Docs in `docs/pages`, bindings in `bindings/`.

- CLI entry: `packages/cli/bin/lodestar.ts` -> `src/cli.ts` (`getLodestarCli`, env prefix `LODESTAR_`, `--rcConfig` file) -> `src/cmds/*` (`cmds/beacon/{index,handler,options}.ts`, `cmds/validator/{handler,options}.ts`).
- CLI options: global in `packages/cli/src/options/globalOptions.ts` (`--network` default `mainnet`, `--supernode`, `--semiSupernode`, `--dataDir`); beacon cmd in `cmds/beacon/options.ts` (`checkpointSyncUrl`, `checkpointState`, `dbDir`); node options groups in `packages/cli/src/options/beaconNodeOptions/{api,builder,chain,eth1,execution,metrics,monitoring,network,sync}.ts`; validator in `cmds/validator/options.ts`. Each option's `default`/`defaultDescription` points at `defaultOptions` from `@lodestar/beacon-node` (`packages/beacon-node/src/node/options.ts`, `chain/options.ts` `defaultChainOptions`, `api/options.ts` `defaultApiOptions`) - the real defaults live there, not in the CLI file.
- Full generated CLI reference: `docs/pages/reference/cli.md` (docsgen in `packages/cli/docsgen`).
- Default ports: REST 9596 (`api/rest/index.ts` `beaconRestApiServerOpts`), keymanager 5062, metrics BN 8008 (`metrics/options.ts`), p2p 9000 (`defaultP2pPort` in `cli/src/options/beaconNodeOptions/network.ts`).

## 2. Beacon API structure

Route definitions are shared by client and server in `packages/api/src`:
- `beacon/routes/*.ts`: one file per namespace: `beacon/{index,block,state,pool,rewards}.ts`, `config.ts`, `debug.ts`, `events.ts`, `lightclient.ts`, `lodestar.ts`, `node.ts`, `proof.ts`, `validator.ts`. Each exports `Endpoints` (typed `Endpoint<method, ReqArgs, ReqRaw, Return, Meta>`) and `getDefinitions(config)` returning `RouteDefinitions` = `{url, method, operationId, req: {writeReq/parseReq (+Json/Ssz variants), schema}, resp: {data codec, meta codec, onlySupport?, isEmpty?, transform?}}`.
- Codecs/helpers: `utils/codecs.ts` (`WithVersion`, `WithMeta`, `EmptyResponseCodec`...), `utils/metadata.ts` (meta codecs: `ExecutionOptimisticFinalizedAndVersionCodec` etc, `MetaHeader` enum), `utils/schema.ts`, `utils/serdes.ts`, `utils/headers.ts` (`MediaType`, `parseAcceptHeader`), `utils/wireFormat.ts`, `utils/httpStatusCode.ts`, `utils/types.ts`.
- Server glue: `src/beacon/server/*.ts` (`registerRoutes` in `server/index.ts` maps namespace -> fastify routes, tags each with the namespace) over generic `utils/server/{handler,route,parser,error,method}.ts` (`createFastifyHandler` = Accept/Content-Type negotiation + codec). Server code is exported separately: `@lodestar/api/beacon/server`, `@lodestar/api/server`.
- Client: `src/beacon/client/*.ts`, `utils/client/{httpClient,request,response,eventSource,error}.ts`.
- Namespaces list: `src/beacon/index.ts` `allNamespaces` = beacon, config, debug, events, lightclient, lodestar, node, proof, validator.
- Server impl in beacon-node: `packages/beacon-node/src/api/impl/` - `api.ts` (`getApi` aggregates), `beacon/{index,blocks,state,pool,rewards}`, `config`, `debug`, `events`, `lightclient`, `lodestar`, `node`, `proof`, `validator`; shared `errors.ts`, `utils.ts` (`notWhileSyncing`, `assertUniqueItems`), `types.ts` (`ApiModules`). Method names match Endpoint keys (e.g. `getBlockV2`, `produceBlockV3`).
- HTTP server: `src/api/rest/{base,index}.ts` (`RestApiServer` on fastify, `BeaconRestApiServer.registerRoutes`), `swaggerUI.ts`, `activeSockets.ts`.

Endpoint map (url in `packages/api/src/beacon/routes/<file>`):
- `/eth/v1/beacon/*` (beacon/index.ts, state.ts, block.ts, pool.ts, rewards.ts): `genesis`; `states/{state_id}/{root,fork,finality_checkpoints,validators(GET+POST),validators/{id},validator_balances(GET+POST),validator_identities,committees,sync_committees,randao,pending_deposits,pending_partial_withdrawals,pending_consolidations,proposer_lookahead,ptc,builders,builder_pending_payments,builder_pending_withdrawals}`; `headers`, `headers/{block_id}`; `v2/beacon/blocks/{block_id}` (+`/attestations`), `blocks/{id}/root`, `blinded_blocks/{id}`, POST `v2/beacon/blocks`, `v2/beacon/blinded_blocks`; `blob_sidecars/{block_id}`, `blobs/{block_id}`; gloas: `execution_payload_envelopes(/{block_id})`, `execution_payload_bids`, `proposer_preferences`; `pool/{attestations(v2),attester_slashings(v2),proposer_slashings,voluntary_exits,bls_to_execution_changes,sync_committees,payload_attestations}`; `rewards/{blocks/{id},attestations/{epoch},sync_committee/{id}}`.

### Using @lodestar/api as a typed TS client
```ts
import {getClient} from "@lodestar/api";
import {createChainForkConfig, defaultChainConfig} from "@lodestar/config"; // use the target network's chain config
const config = createChainForkConfig({...defaultChainConfig});
const api = getClient({baseUrl: "http://localhost:9596"}, {config});
const res = await api.beacon.getBlockV2({blockId: "head"});
res.assertOk();              // throws ApiError (status, message) on non-2xx
const block = res.value();   // typed, fork-aware
const {executionOptimistic, finalized, version} = res.meta();
```
- Every call returns `ApiResponse` (a `Response` subclass): `.ok`, `.status`, `.value()`, `.meta()` (executionOptimistic, finalized, version), `.assertOk()` throws `ApiError`, `.wireFormat()`, `.rawBody()`, `.error()`. `HttpClientOptions`: `baseUrl` (string or array = fallback urls with scoring, `utils/client/httpClient.ts`), `globalInit` (`timeoutMs` default 60000, `retries` default 0, `retryDelay` 200, `requestWireFormat` default json, `responseWireFormat` default ssz), per-call 2nd arg overrides. Config's fork schedule must match target network or fork-versioned decoding fails.
- Events: `api.events.eventstream({topics:[...], signal, onEvent})`.

## 3. Behaviour

### Errors & status codes
- Body format `{code, message, stacktraces?}` (set in `api/rest/base.ts` `setErrorHandler`; stacktraces only with `--rest.stacktraces`). Batch submissions return `{code, message, failures:[{index,message}]}` via `IndexedError` (400).
- `ApiError(statusCode, msg)` in `packages/api/src/utils/server/error.ts`; subclasses in `beacon-node/src/api/impl/errors.ts`: `StateNotFound` 404 "State not found", `DataNotAvailable` 404, `ValidationError` 400, `NodeIsSyncing` 503 `"Node is syncing - ..."`, `OnlySupportedByDVT` 501, `IndexedError` 400.
- Mapping: schema/param validation -> 400 (`"<field> <ajv message>"`), parse errors in `createFastifyHandler` -> 400, bad Accept -> 406, bad Content-Type -> 415 (also `onlySupport` endpoints), unknown route -> 404 `Route GET:/x not found`, `GossipActionError` -> 400, ANY other thrown `Error` -> 500 (so many "unavailable" conditions are 500, see quirks). Missing auth on keymanager -> 401 from `@fastify/bearer-auth`.
- Query arrays: comma-separated only (`id[0]=..` not supported); array cap = `NUMBER_OF_COLUMNS` (`QUERY_STRING_ARRAY_LIMIT` in `base.ts`).

### 503 / syncing
- `notWhileSyncing(chain, sync.state)` in `api/impl/utils.ts`: only throws when sync state is `SyncingFinalized|SyncingHead` AND `currentSlot - headSlot > SYNC_TOLERANCE_EPOCHS(=1) * SLOTS_PER_EPOCH`, or `Stalled` ("waiting for peers"). Never throws when `clock.currentSlot < SLOTS_PER_EPOCH`.
- Used by: all validator duties (attester/proposer/sync/ptc/inclusion-list), `attestation_data`, `payload_attestation_data`, aggregate fetch/publish, contribution publish, subnet subscriptions, `produceBlockV3/V4`, `getExecutionPayloadEnvelope`, and beacon state lookups EXCEPT `head|finalized|justified|genesis` state ids (`getStateResponseWithRegen` in `api/impl/beacon/state/utils.ts`). So `/beacon/states/head/*` works while syncing; `states/<slot>` or `<root>` gives 503.
- Block production also 503s if parent block is optimistic (`isOptimisticBlock`, EL status Syncing) or its data is `OutOfRange` (`notOnOutOfRangeData`). Sync-committee message endpoints use `notOnOptimisticBlockRoot`.
- `/eth/v1/node/health`: 200 ready; `syncing_status` query overrides the not-ready code; default not-ready = 206 (`routes.node.NodeHealth.SYNCING`) when `isSyncing || isOptimistic || elOffline` (`getHealth` in `api/impl/node/index.ts`). 503 "not initialized" can never be served: the API starts only after init. `/node/syncing`: `sync.getSyncStatus()` in `sync/sync.ts` returns `{headSlot, syncDistance, isSyncing, isOptimistic, elOffline}` (`elOffline` = EL state OFFLINE or AUTH_FAILED).

### state_id / block_id resolution
- `resolveStateId` (`state/utils.ts`): `head` (head stateRoot), `genesis` (slot 0), `finalized`/`justified` (checkpoints), `0x..` (state root), else decimal slot (non-numeric -> 400 ValidationError). `resolveBlockId` (`beacon/blocks/utils.ts`): same keywords + 0x block root (regex-validated 32 bytes) + slot; case-insensitive.
- State lookup `getStateResponseWithRegen`: head -> `regen.getStateSync(head.stateRoot)` fallback `chain.getHeadState()`; root -> `chain.getStateByStateRoot(root,{allowRegen:true})`; slot > currentSlot -> 404; slot >= finalized slot -> `chain.getStateBySlot(allowRegen)` (regen from closest canonical block, `RegenCaller.restApi`); slot < finalized -> `chain.getHistoricalStateBySlot` (`chain/chain.ts` -> `archiveStore.getHistoricalStateBySlot`); checkpoint -> `getStateOrBytesByCheckpoint`. Not found -> `ApiError(404, "State not found for id '<id>'")`.
- Historical state availability: ONLY with `--serveHistoricalState` (default false; `defaultChainOptions.serveHistoricalState`). Without it `getHistoricalStateBySlot` throws plain `Error("Historical state regen is not enabled, set --serveHistoricalState ...")` => HTTP 500 (not 404). With it, states regenerated on demand from archived states; archived every `--chain.archiveStateEpochFrequency` (default 1024 epochs) by `chain/archiveStore/` (`ArchiveMode.Frequency` is the only mode, `--chain.archiveMode` hidden); only states since genesis/checkpoint-sync anchor are regenerable (no backfill). `--chain.pruneHistory` (default false) prunes blocks older than `MIN_EPOCHS_FOR_BLOCK_REQUESTS` (33024 epochs mainnet) and archived states before finalized. State by root for old finalized roots only works if in cache or archived (`stateArchive.getBinaryByRoot`; mostly useful with `archiveStateEpochFrequency 1`).
- In-memory state caches: `chain/stateCache/` (block states `--chain.maxBlockStates`, checkpoint states in memory `--chain.maxCPStateEpochsInMemory`, persisted to disk `nHistoricalStatesFileDataStore` default true, `--chain.maxCPStateEpochsOnDisk`); `regen/` does replay. `POST /eth/v1/lodestar/drop_state_cache` clears.
- Block lookup `getBlockResponse`: by root -> `chain.getBlockByRoot` (fork choice -> seen block input cache -> hot db -> `blockArchive`); by slot -> `getCanonicalBlockAtSlot` (fork choice for unfinalized else `blockArchive`). Missing (including skipped slot) -> 404 `Block not found for id '<id>'`. Finalized/archived blocks return `executionOptimistic:false, finalized:true`.

### Content negotiation, headers, flags
- `createFastifyHandler` (`api/src/utils/server/handler.ts`): `Accept` absent -> JSON; `application/octet-stream` -> SSZ (q-values honored, `*/*` -> JSON); endpoint `onlySupport` restricts. Response `Content-Type` is `application/json` or `application/octet-stream`. SSZ requests need `Content-Type: application/octet-stream` (parser `addSszContentTypeParser`); POST bodies must also carry `Eth-Consensus-Version` where required (e.g. publish blocks, aggregates, attestations v2: `MetaHeader.Version` in `routes/validator.ts`/`beacon/*.ts`).
- Metadata is emitted BOTH in JSON body (`version`, `execution_optimistic`, `finalized`, `dependent_root`) and as headers (`utils/metadata.ts` `MetaHeader`): `Eth-Consensus-Version`, `Eth-Execution-Optimistic`, `Eth-Consensus-Finalized`, `Eth-Consensus-Dependent-Root`, `Eth-Consensus-Block-Value`, `Eth-Execution-Payload-Value`, `Eth-Execution-Payload-Blinded`, `Eth-Execution-Payload-Source`; plus `Access-Control-Expose-Headers`. `Eth-Consensus-Finalized` / `Eth-Execution-Payload-Source` are Lodestar-specific (non-standard).
- `execution_optimistic` = `isOptimisticBlock(block)` (`util/forkChoice.ts`: ExecutionStatus.Syncing). `finalized` = true for archived data; for fork-choice data computed from epoch vs finalized checkpoint (state paths: `state.epoch <= finalizedEpoch && finalizedEpoch !== GENESIS_EPOCH`); unfinalized blocks always `finalized:false`.
- `blindedLocal` / `payloadLocal` etc. are VC flags (see section 5). `skipRandaoVerification` is accepted but ignored (TODO in code).

### Limits / CORS / ports / namespaces
- `rest.*` defaults (`beaconRestApiServerOpts` in `api/rest/index.ts`): enabled true, namespaces `["beacon","config","debug","events","node","validator","lightclient"]` (NOT `lodestar`, NOT `proof`), address `127.0.0.1`, port 9596, cors `*` (`--rest.cors all` coerces to `*`), bodyLimit 20 MiB (`--rest.bodyLimit`, hidden), `--rest.headerLimit`, `--rest.swaggerUI` (docs at `/documentation`), stacktraces false. No rate limiting anywhere in the REST server (no 429 path); no per-request timeout on the server except SSE keepalive. Shutdown force-terminates sockets (`HttpActiveSocketsTracker`). Warns if bound to non-localhost.
- BN REST has no auth (`bearerToken` only used by keymanager server).
- `GET` requests for slots in the future: producers `waitForSlot`; `MAX_API_CLOCK_DISPARITY_MS` = 1000 for publish; attester duties wait for next closest epoch and 400 if epoch > current+1.

### SSE topics (`EventType` in `routes/events.ts`; subscribe with `topics=a,b`)
`head, head_v2, block, block_gossip, attestation, single_attestation, voluntary_exit, proposer_slashing, attester_slashing, bls_to_execution_change, finalized_checkpoint, chain_reorg, contribution_and_proof, light_client_optimistic_update, light_client_finality_update, payload_attributes, blob_sidecar, data_column_sidecar, execution_payload, execution_payload_gossip, execution_payload_available, execution_payload_bid, proposer_preferences, payload_attestation_message, inclusion_list, fast_confirmation`. Unknown topic -> 400 (schema enum). `payload_attributes` only emitted when `--emitPayloadAttributes` (default false).

### Blobs / data columns (PeerDAS / Fulu)
- `GET /eth/v1/beacon/blob_sidecars/{block_id}` and `/blobs/{block_id}` (`getBlobSidecars`, `getBlobs` in `api/impl/beacon/blocks/index.ts`):
  - Block resolved first via `getBlockResponse` (404 if block unknown/pruned).
  - Pre-Deneb -> `[]`. Deneb..pre-Fulu: from `chain.getBlobSidecars` (seen cache -> `db.blobSidecars` -> `db.blobSidecarsArchive`); not found -> 404 `blobSidecars not found in db for slot=.. root=..`.
  - Fulu+: reconstructed from data columns (`reconstructBlobs`, KZG proofs recomputed for sidecars). If node custody `targetCustodyGroupCount < NUMBER_OF_COLUMNS/2` (i.e. < 64 columns custodied; default non-supernode custodies `CUSTODY_REQUIREMENT`=4 groups, validator custody can raise up to 8+) -> **503** `"Custody group count of N is not sufficient to serve blob sidecars, must custody at least 64 data columns"`. Needs `--supernode` (all 128 groups) or `--semiSupernode` (half = 64 groups, `cli/src/cmds/beacon/handler.ts` ~L267). If blobs exist but no columns stored (pruned/not custodied) -> 404 `dataColumnSidecars not found in db...`. `indices` out of range -> 400; duplicates -> 400; `versioned_hashes` not in block -> 400.
  - Block with 0 blobs -> 200 `[]`.
- `GET /eth/v1/debug/beacon/data_column_sidecars/{block_id}` (`getDebugDataColumnSidecars` in `api/impl/debug/index.ts`): returns only columns this node custodies; if none found for a block with blobs it throws plain `Error` => 500 (not 404).
- Retention: blob sidecars (Deneb..pre-Fulu) pruned at finalization in `chain/archiveStore/utils/archiveBlocks.ts`: keep `max(MIN_EPOCHS_FOR_BLOB_SIDECARS_REQUESTS (4096 mainnet), archiveDataEpochs)`. Data columns (Fulu+): keep from `min(getBlobDataRetentionStartEpoch(config, epoch), epoch - archiveDataEpochs)` (`getDataColumnSidecarsMinEpoch`; window `MIN_BLOB_DATA_RETENTION_MS` = 1572864000 ms ~ 18.2 days mainnet, `packages/state-transition/src/util/slot.ts`). Flag: `--chain.archiveDataEpochs` (alias `--chain.archiveBlobEpochs`; `Infinity` disables pruning). Columns stored as flat files in `$dataDir/data_columns` (`--dataColumnDir`).
- Custody config: `CustodyConfig` in `packages/beacon-node/src/util/dataColumns.ts`; cgc persisted in ENR (`cgc`) and never reduced across restarts (warn in handler); `--persistNetworkIdentity` (default true) set to false resets validator custody (see `cmds/beacon/options.ts`).
- Post-Gloas: columns are published/stored with the execution payload envelope (`seenPayloadEnvelopeInputCache`), not with the block.

## 4. Engine API client (packages/beacon-node/src/execution/)
- `execution/index.ts`, `engine/{index,http,interface,transport,jsonRpcTransport,restTransport,jsonRpcHttpClient,restHttpClient,jwt,types,sszTypes,utils,payloadIdCache,mock,disabled}.ts`. `initializeExecutionEngine` (`engine/index.ts`): mode `http` (default) | `mock` (`--execution.engineMock`) | `disabled`.
- Class `ExecutionEngineHttp` (`engine/http.ts`) implements `IExecutionEngine`: `notifyNewPayload`, `notifyForkchoiceUpdate`, `getPayload`, `getPayloadBodiesByHashV2`, `getBlobs` (V1 pre-Fulu, V2 Fulu+), `getInclusionList`, `getClientVersion`. All newPayload/fcU go through a `JobItemQueue` (serialized; max length `EPOCHS_PER_BATCH * SLOTS_PER_EPOCH * 2`).
- Transports: legacy JSON-RPC (`jsonRpcTransport.ts`) and the new REST+SSZ engine API (`restTransport.ts`: `/capabilities`, `/payloads`, `/forkchoice`, `/payloads/{id}`, `/bodies/hash`, `/blobs/v1|v2`, `/identity`). `--execution.engineApi auto|ssz|json-rpc` (default `auto`): REST only with exactly one URL and when EL advertises capabilities; falls back to JSON-RPC for multiple URLs, unadvertised forks/blob revisions; `ssz` requires exactly one URL (`ENGINE_REST_REQUIRES_SINGLE_URL`).
- Method versions by fork (JSON-RPC): newPayload V1 (bellatrix), V2 (capella), V3 (deneb), V4 (electra/fulu), V5 (gloas), V6 (heze; requires inclusionListTransactions); forkchoiceUpdated V1/V2(capella)/V3(deneb..fulu)/V4(gloas)/V5(heze); getPayload V1 (<=bellatrix) V2 capella V3 deneb V4 electra V5 fulu V6 default(gloas+); getBlobsV1/V2 (max 128 hashes per request, `MAX_VERSIONED_HASHES`); getPayloadBodiesByHashV2; getClientVersionV1; getInclusionListV1 (JSON-RPC only).
- Config defaults (`defaultExecutionEngineHttpOpts`): urls `["http://localhost:8551"]`, `timeout` 12000 ms, `retries` 2, `retryDelay` 2000 ms. Flags: `--execution.urls` (comma list, extra URLs are fallbacks tried in order in `JsonRpcHttpClient.fetch`), `--execution.timeout`, `--execution.retries` (alias `retryAttempts`), `--execution.retryDelay`, `--jwtSecret <file>`, `--jwtId`. Raw client fallback timeout 30 s if no opts. fcU without payload attributes uses `retries: 0` (next fcU supersedes it); fcU with attributes retries.
- JWT: `engine/jwt.ts` (`encodeJwtToken`, HS256, claims `iat`, optional `id`, `clv`); a fresh token is generated per request (EL checks +-5 s). Secret file is hex (`extractJwtHexSecret`, accepts optional 0x). Without `--jwtSecret` no auth header is sent. REST API drops `clv` claim and sends `X-Engine-Client-Version` instead.
- newPayload result handling (`notifyNewPayload` then `chain/blocks/verifyBlocksExecutionPayloads.ts`): VALID -> import as Valid; INVALID -> `BlockError EXECUTION_ENGINE_INVALID` + invalidate from LVH (`lvhResponse`); SYNCING/ACCEPTED -> import optimistically (`ExecutionStatus.Syncing`; "post-merge always safe to optimistically import"); INVALID_BLOCK_HASH / ELERROR / UNAVAILABLE -> `BlockError EXECUTION_ENGINE_ERROR` (block not imported, no fork-choice invalidation). Transport/HTTP errors in newPayload are converted to status UNAVAILABLE (network) or ELERROR (EL replied error) instead of throwing.
- fcU result (`notifyForkchoiceUpdate`): VALID ok (payloadId required when attributes sent, cached in `PayloadIdCache`); SYNCING throws `"Execution Layer Syncing"` only if attributes were requested (block production) else ignored; INVALID throws `Invalid prepare payload/forkchoice request`.
- EL state tracking: `ExecutionEngineState` {ONLINE (initial), OFFLINE, SYNCING, SYNCED, AUTH_FAILED}, computed by `getExecutionEngineState` (`engine/utils.ts`): VALID/ACCEPTED -> SYNCED; SYNCING/INVALID/ELERROR -> SYNCING; UNAVAILABLE or ECONNREFUSED/ENOTFOUND/EAI_AGAIN -> OFFLINE; REST 401/403 or ECONNRESET/ECONNABORTED -> AUTH_FAILED; JSON-RPC/REST response errors -> SYNCING. Consumed by `sync/sync.ts` (`elOffline` in `/node/syncing` + health) and `node/notifier.ts`. Leaving OFFLINE/AUTH_FAILED resets REST capability probing.
- Optimistic sync: fork choice `ExecutionStatus` (Valid/Syncing/Invalid/PreMerge); `isOptimisticBlock`; VC/duties blocked per section 3; `chain/blocks/verifyBlocksExecutionPayloads.ts` is the place to look for status mapping and LVH-based invalidation.
- Block production: `chain.produceBlock` -> fcU(with `PayloadAttributes`) -> `getPayload`; `shouldOverrideBuilder` from EL forces local payload.
- Dev/mock: `--execution.engineMock` (`engine/mock.ts`). Docs for EL setup: `docs/pages/run/getting-started/`.

- Builder (pre-Gloas, trusted builder/relay or mev-boost): BN flags `--builder` (default false), `--builder.url` (default `http://localhost:8661`; only ONE url allowed, error if comma list), `--builder.timeout` (12000), `--builder.faultInspectionWindow`, `--builder.allowedFaults` (`getFaultInspectionParams` in `execution/builder/http.ts`: window default random in [32,64) slots, min 32; allowedFaults capped to window/4). `ExecutionBuilderHttp`: `registerValidator` (cached in `ValidatorRegistrationCache`), `getHeader` (timeout 1250 ms = `BUILDER_PROPOSAL_DELAY_TOLERANCE`), `submitBlindedBlock(V2)` (retries 2, SSZ after server proves SSZ support), `checkStatus`. Statuses `BuilderStatus` enabled/disabled/circuit_breaker.
- Block production race (`produceEngineOrBuilderBlock` in `api/impl/validator/index.ts`, used by `produceBlockV3`): builder and engine run in parallel; wait cutoff `BLOCK_PRODUCTION_RACE_CUTOFF_BPS = 1667` (1/6 slot ~2 s mainnet) then proceeds with whichever resolved (hard timeout = slot duration). Rules in order: engine `shouldOverrideBuilder` (EL signals censorship) -> engine; builder boost 0 or `executionalways` -> engine (aborts builder wait); only builder result -> builder ("engine_pending/error"); only engine result -> engine (reasons logged/metric `blockProductionSelectionResults`: builder_disabled, no_bid, timeout, pending, error, circuit_breaker); both -> `selectBlockProductionSource` (`api/impl/validator/utils.ts`): `executionalways|executiononly` -> engine; `builderalways` (and legacy `builderonly`, remapped with a warning) -> builder; `default|maxprofit` -> `selectBlockProductionSourceByBoostFactor`: boost 0 -> engine; boost == `MAX_BUILDER_BOOST_FACTOR` (2^64-1) -> builder; else engine if `engineValue*100 >= builderValue*boostFactor`, else builder. Both fail -> 500 error. Default `builderBoostFactor` 100n when absent; > max -> 400. Builder is skipped when `builderSelection=executiononly`, no `chain.executionBuilder`, or circuit breaker active.
- VC-side defaults (`packages/validator/src/services/validatorStore.ts` `defaultOptions`): `builderSelection` = `executiononly` pre-Gloas (so `--builder` alone on the BN is not enough; VC needs `--builder` (alias for `--builder.selection default`... i.e. `builderAliasSelection`=`default`) or `--builder.selection maxprofit|builderalways`), `default` post-Gloas (`getDefaultBuilderSelection`); `builderBoostFactor` 100n; `builderMinBid` 0; `builderMaxExecutionPayment` 0; `blindedLocal` false. VC flags: `--builder`, `--builder.selection` (`default|maxprofit|builderalways|executionalways|executiononly`), `--builder.boostFactor` (only effective for maxprofit), `--builder.minBid`, `--builder.urls`, `--builder.maxExecutionPayment` (>0 needs `--allowDangerousTrustedPayments`). `executiononly` + builder urls is rejected at startup. Per-key overrides: proposer config file (`docs/pages/run/validator-management/proposer-config.md`) or keymanager `builder_boost_factor` / `builder_config`.
- Post-Gloas (ePBS): `produceBlockV4` takes `builderConfig` (`minBid`, `builderBoostFactor`, `builders[]` with url, auth, pubkeys, per-entry boost); BN requests bids from builder API(s) via `chain.builderApiClient.getExecutionPayloadBids` in parallel with local build, also considers p2p bids, ranks via `compareBidCandidates` (max-boost first, then boosted total payment, builder-API over p2p, earlier receipt). Local self-build uses `BUILDER_INDEX_SELF_BUILD`. Circuit breaker: `chain/builderCircuitBreaker.ts` (`--builder.faultInspectionWindow/allowedFaults` mean canonical EMPTY block rate here). `registerValidator` returns 400 post-Gloas; use `POST /eth/v1/validator/builder_preferences`. BN flag `--builder*` is "pre-Gloas only, deprecated".
- Fee recipient / graffiti: `prepare_beacon_proposer` feeds `chain.beaconProposerCache`; graffiti via `getBlockGraffiti` (appends client version `graffitiAppend` default true unless `--private`).
- Docs: `docs/pages/run/beacon-management/mev-and-builder-integration.md` (partly stale: describes pre-selection "prefer builder").

## 6. Quirks / deviations
- Many "data missing" paths throw plain `Error` => **500** instead of 404: historical state without `--serveHistoricalState`; `getDebugDataColumnSidecars` when columns missing; light client `optimistic_update`/`finality_update` with no update ("No optimistic update available"); `getLodestar persisted_checkpoint_state` when flag disabled. Blob endpoints do return 404 for missing stored data and **503** (spec-unusual) for insufficient custody.
- `head|finalized|justified|genesis` state ids bypass the syncing 503; other ids do not.
- Non-standard headers `Eth-Consensus-Finalized`, `Eth-Consensus-Dependent-Root`, `Eth-Execution-Payload-Source`; events `head_v2`, `block_gossip`, `execution_payload_*` etc. track newer beacon-APIs drafts (tests pin OpenAPI `v5.0.0-beta.0`, consensus-specs `v1.7.0-beta.4` in `spec-tests-version.json`).
- Query arrays must be comma-separated; `id[0]=` style is rejected (400).
- SSE: no event replay, no `Last-Event-ID`; per-event serialization failure only drops that event; listener errors are swallowed and logged.
- Publish block (`publishBlockV2`): default `broadcast_validation=gossip`; holds early blocks (<=1 s before slot) until slot start; already-known blocks return success; `consensus_and_equivocation` returns 400 with conflicting roots; locally-produced blocks (in `chain.blockProductionCache`) skip re-validation; blocks are gossiped before import. Publish may return 4xx/5xx after already publishing (spec: block is sent regardless).
- `getBlockV2` / `getStateV2` return fork version header; `POST` endpoints accept SSZ only if documented in route def (`onlySupport` / `req.onlySupport`).
- `/eth/v1/beacon/states/{id}/validators` default statuses filter via `filterStateValidatorsByStatus`; builder endpoints 400 pre-gloas; `pending_*` endpoints 400 pre-electra, `proposer_lookahead` 400 pre-fulu, `ptc` 400 pre-gloas, sync_committees 400 pre-altair.
- Only a single `--builder.url`; multi-relay requires mev-boost.
- `node/version` returns `Lodestar/<version>/...` string from `opts.version` (`"dev"` if not injected).
- Engine: JSON-RPC multiple URLs act as fallbacks (not load-balancing); REST engine transport only with one URL.
