## 2. Beacon API: where it is defined

- Server setup: `beacon-chain/node/node.go` (`registerHTTPService`, ~line 1117) builds `httprest.New` (`api/server/httprest/server.go`) with middleware `NormalizeQueryValuesHandler` (comma-separated query values become repeated keys) then `CorsHandler`. Router is a stdlib `http.ServeMux` (Go 1.22 patterns) created in node.go and passed as `rpc.Config.Router`.
- Route registry: `beacon-chain/rpc/endpoints.go`. `(*Service).endpoints()` aggregates per-namespace builders: `rewardsEndpoints`, `blobEndpoints`, `validatorEndpoints`, `nodeEndpoints`, `beaconEndpoints`, `configEndpoints`, `eventsEndpoints`, `prysmBeaconEndpoints`, `prysmNodeEndpoints`, `prysmValidatorEndpoints`, `removedEndpoints`, plus `lightClientEndpoints` (only if `--enable-light-client`) and `debugEndpoints` + `removedDebugEndpoints` (unless `--disable-debug-rpc-endpoints`). Each `endpoint{template, name, middleware, handler, methods}`; per-route middleware = `ContentTypeHandler` (415 if body type not in allowed list), `AcceptHeaderHandler` (406 if Accept unsatisfiable), `AcceptEncodingHeaderHandler` (gzip for JSON only). Registration loop is in `beacon-chain/rpc/service.go` (`NewService`, `s.cfg.Router.HandleFunc(...)`). Prometheus metrics per endpoint name in `beacon-chain/rpc/metrics.go`.
- To find the handler for a route: grep the path template in `beacon-chain/rpc/endpoints.go`, read `handler: server.X`, then grep `func (s \*Server) X` in the matching package.
- Handlers by namespace (`beacon-chain/rpc/eth/...`):

## 3. Behaviour

### Errors and status codes
- Error body: `{"code": <int>, "message": "<string>"}` (`network/httputil/writer.go` `DefaultJsonError`, `HandleError`, `WriteError`). Multi-item failures (pool submits): `IndexedErrorContainer{message, code, failures:[{index,message}]}` in `api/server/error.go`, 400 with message "One or more messages failed validation".
- Middleware errors (415/406) use `http.Error` so bodies are plain text, not JSON (`api/server/middleware/middleware.go`). Quirk vs spec.
- Mapping helpers: `beacon-chain/rpc/eth/shared/errors.go` (`WriteStateFetchError`: state/root not found -> 404, bad id -> 400, else 500; `WriteBlockFetchError`: not found/nil block -> 404, bad id -> 400, else 500); `beacon-chain/rpc/core/errors.go` (`ErrorReasonToHTTP`: Internal 500, Unavailable 503, BadRequest 400, NotFound 404, NoContent 204).
- 503 sources: `shared.IsSyncing` in `beacon-chain/rpc/eth/shared/request.go` (message "Beacon node is currently syncing and not serving request on that endpoint Details: {...head_slot, sync_distance, is_syncing, is_optimistic}") is called by validator endpoints (`validator/handlers.go`, `handlers_builder.go`), `PublishBlockV2`, `PublishBlindedBlockV2`. `ProduceBlockV3`: 503 "The node is currently optimistic and cannot serve validators" (checked after building a post-Bellatrix block). `/prysm/v1/node/custody`: 503. `GetHealth`: see below. State/block/header GET endpoints do NOT return 503 while syncing; they serve whatever is in the DB/head.
- `/eth/v1/node/health`: 200 synced and not optimistic; 206 if syncing OR optimistic (override with `?syncing_status=<code>`, validated as HTTP status text); 503 if neither synced nor syncing (`node/handlers.go` `GetHealth`). Note 206 for optimistic.
- `/eth/v1/node/syncing` returns `head_slot, sync_distance, is_syncing, is_optimistic, el_offline` (`ElOffline = !ExecutionClientConnected()`).
- Block publish (`beacon/handlers.go` `publishBlock`, `publishBlockSSZ`): JSON requires nothing extra for v2 if the `Eth-Consensus-Version` header is absent: it is derived from the slot in the body (`versionHeaderFromRequest`, via fork epochs); for SSZ the header is required. `broadcast_validation` = `gossip` | `consensus` | `consensus_and_equivocation` (`validateBroadcast`); validation failures return 400 (equivocation also re-broadcasts sidecars). `proposeBlock` returns 500 on any `ProposeBeaconBlock` error. This node never emits the spec's 202 (block broadcast but failed import) from these handlers (grep found no `StatusAccepted` in `beacon-chain/rpc/eth`).
- `GetBlockV2` on a blinded stored block calls `ExecutionReconstructor.ReconstructFullBlock` (asks the EL via `engine_getPayloadBodiesByHash*`); failure returns 400 "could not reconstruct full execution payload...". So block GETs can fail when the EL is down or has pruned the payload.
- Rate limiting: none on the REST server (the only "rate limit" is `broadcastBLSChangesRateLimit = 128` for BLS-change rebroadcast). Timeouts: `--api-timeout` (`cmd/flags.go` `ApiTimeoutFlag`, declared default 10s). In `node.go` it is only applied `if IsSet(...)`, so by default there is no `http.TimeoutHandler` and only `ReadHeaderTimeout` 1s; when set, `http.TimeoutHandler` returns 503 "request timed out" and `/eth/v1/events` is exempt (`httprest/server.go`). (The IsSet-only application is a code reading, not tested.)
- CORS: `--http-cors-domain` (default list `DefaultHTTPCorsDomains` in `cmd/beacon-chain/flags/base.go`: localhost/127.0.0.1/0.0.0.0 on port 3000 plus web/http-server domains); methods POST, GET, DELETE, OPTIONS; credentials allowed; max-age 600 (`middleware.CorsHandler`).
- Pagination cap: `cmd.Get().MaxRPCPageSize` (flag `RPCMaxPageSizeFlag` in `cmd/flags.go`, default `params.BeaconConfig().DefaultPageSize`), used by gRPC lists.

### state_id / block_id resolution
- `beacon-chain/rpc/lookup/stater.go` `BeaconDbStater.State`: `head` (head state), `genesis` (`StateBySlot(genesis)`), `finalized` / `justified` (replay to start slot of the checkpoint epoch via `ReplayerBuilder`, so slot is epoch-start, not the checkpoint block's slot), `<slot>` (decimal), `0x`-hex state root. Invalid -> `StateIdParseError` -> 400.
- State by root is only found by scanning the head state's `state_roots` ring buffer (`stateByRoot`): window is `SLOTS_PER_HISTORICAL_ROOT` (8192 slots, ~27 h on mainnet) back from head. Older roots -> 404 "state not found in the last N state roots". Post-Gloas it also matches pre-payload state roots via the block's state root.
- By slot (`StateBySlot`): 404 if slot is in the future; 404 if `slot < EarliestSlot` (checkpoint-sync start) or below backfill `LowSlot`; with `--enable-state-diff` serves state-diff tree boundary slots directly (`stateFromDiffTree`); otherwise replays blocks from the nearest saved state (`ReplayerBuilder...ReplayBlocks`); `stategen.ErrNoDataForSlot` -> 404 "historical data not available". Archive: `--enable-archive` (implies `--enable-state-diff` + backfill) regenerates every historical state into the state-diff tree down to `--archive-origin-state` (default genesis); `--state-diff-exponents` default `21,18,16,13,11,9,5`. Without those, hot states are persisted every `defaultHotStateDBInterval = 128` slots (`beacon-chain/state/stategen/service.go`) and finalized history is replayed from the nearest snapshot (slow for old slots). `--slots-per-archive-point` (default 2048) is a legacy cold-state knob (`beacon-chain/node/config.go`); `--historical-slasher-node` sets it to 4 epochs and raises page size.
- Blocks (`lookup/blocker.go` `resolveBlockID`): `head`, `genesis`, `finalized`, `justified`, `0x` root, or slot. By slot returns the canonical block only (iterates `BlockRootsBySlot`, checks `IsCanonical`), else 404 "no canonical block found at slot N" (skipped slot is 404, not the prior block). Headers `GET /headers` with no params returns head slot; zero blocks -> 404 "No blocks found".
- `execution_optimistic` and `finalized`: computed per response. State endpoints: `beacon-chain/rpc/eth/helpers/sync.go` `IsOptimistic(stateId)` (special-cases head/genesis/finalized/justified/root/slot, using `LastValidatedCheckpoint` for slots while optimistic). `finalized` via `FinalizationFetcher.IsFinalized(ctx, root)`. Block endpoints: `OptimisticModeFetcher.IsOptimisticForRoot`.
- `Eth-Consensus-Version` is set on block/state/blob/debug responses and block production (`api/headers.go`: also `Eth-Execution-Payload-Blinded`, `Eth-Execution-Payload-Value`, `Eth-Consensus-Block-Value`, `Eth-Builder-Url`, `Eth-Blob-Data-Included`); JSON bodies also carry `version`.

### SSZ vs JSON
- `httputil.RespondWithSsz(r)` (`network/httputil/reader.go`): looks only at the FIRST `Accept` header value, parses `q=` weights, returns SSZ iff `application/octet-stream` has strictly higher q than `application/json` (ties go to JSON; no Accept = JSON). Request bodies: `Content-Type: application/octet-stream` = SSZ (`IsRequestSsz`). Endpoints list their allowed types in `endpoints.go`; those with only `JsonMediaType` in `AcceptHeaderHandler` return 406 for SSZ. SSZ-capable GETs include blocks, blinded blocks, blob/data-column sidecars, validator_balances/identities, pending_* lists, proposer_lookahead, debug state, attestation_data, aggregate_attestation v2, produceBlockV3/V4.

### Blobs / data columns (`lookup/blocker.go`)
- `resolveBlobsContext`: `genesis` -> 400; slot before Deneb -> 400 "blobs are not supported before Deneb fork"; versioned_hashes not in block -> 404 listing missing. Block with zero commitments -> 200 empty list.
- Pre-Fulu blocks (`blobsFromStoredBlobs`, `blobsDataFromStoredBlobs`): read from `BlobStorage` (`--blob-path`, default `blobs/` next to db; layout `--blob-storage-layout`). Explicit `indices` not present -> 404 "requested index N not found"; index >= max blobs -> 400. With NO `indices`, returns only what is stored (so pruned blobs give 200 with an empty `data` array, not 404; derived from code, not run). `blob_sidecars` validates `indices` against `MaxBlobsPerBlock(slot)` -> 400 "requested blob indices [...] are invalid".
- Post-Fulu blocks: blob endpoints are reconstructed from stored data columns (`blobSidecarsFromStoredDataColumns`, `blobsDataFromStoredDataColumns`, `peerdas.ReconstructBlobs`). If fewer than `MinimumColumnCountToReconstruct()` = (NUMBER_OF_COLUMNS+1)/2 = 64 columns stored -> 404 with text "the node does not custody enough data columns to reconstruct blobs - please start the beacon node with the `--supernode`/`--semi-supernode` flag...". `/blobs` mentions `--semi-supernode`, `/blob_sidecars` mentions `--supernode`.
- Custody (`beacon-chain/sync/service.go` `updateCustodyInfoInDB`): default custody groups = `CustodyRequirement` 4 of `NumberOfCustodyGroups` 128 (validators raise it via `ValidatorCustodyRequirement` 8 and balance, `BalancePerAdditionalCustodyGroup`); `--supernode` (alias `--subscribe-all-data-subnets`) = all 128 groups; `--semi-supernode` = max(requirement, minimum to reconstruct = 64 groups); the two are mutually exclusive (`cmd/beacon-chain/flags/config.go`). A default (non-super) node therefore cannot serve `/blobs` or `/blob_sidecars` for post-Fulu blocks (404). Prysm-only: `/prysm/v1/node/custody` reports custody (`IsSemiSupernode` etc.).
- Retention: `MinEpochsForBlobsSidecarsRequest` 4096 epochs (~18 days) and `MinEpochsForDataColumnSidecarsRequest` 4096; `--blob-retention-epochs` (alias `--extend-blob-retention-epoch`) can only extend (node exits if below 4096), applied to both blobs and columns (`beacon-chain/das/needs.go`). Block history: `MinEpochsForBlockRequests` 33024 (~5 months); db pruning flag `--beacon-db-pruning` and `--pruner-retention-epochs` in `cmd/beacon-chain/flags/base.go` (ignored if below the spec minimum). Backfill: `--enable-backfill`, `--backfill-oldest-slot`.
- `GET /eth/v1/debug/beacon/data_column_sidecars/{block_id}` (`debug/handlers.go` `DataColumnSidecars`, only when debug endpoints are on): genesis/pre-Fulu -> 400; no commitments -> 200 empty; no `indices` -> columns this node custodies; index >= 128 -> 400; Gloas has a different JSON shape (`DataColumnSidecarGloas`).
- Engine `getBlobs`: prysm uses `engine_getBlobsV2` (Fulu), V1 (Deneb/Electra), and V3 / `engine_hasBlobs` when partial data columns are enabled; `--disable-get-blobs-v2` hidden flag; `--disable-partial-data-columns` defaults true. Capability-gated via `capabilityCache` (`beacon-chain/execution/engine_jsonrpc.go`).

### SSE (`/eth/v1/events`, `beacon-chain/rpc/eth/events/events.go`)
- Topics (constants at top of file): `head`, `head_v2`, `block`, `block_gossip`, `attestation`, `single_attestation`, `voluntary_exit`, `finalized_checkpoint`, `chain_reorg`, `contribution_and_proof`, `bls_to_execution_change`, `payload_attributes`, `fast_confirmation`, `blob_sidecar`, `data_column_sidecar`, `proposer_slashing`, `attester_slashing`, `light_client_finality_update`, `light_client_optimistic_update`, `execution_payload`, `execution_payload_available`, `execution_payload_gossip`, `execution_payload_bid` (recognized but never fired), `payload_attestation_message`, `proposer_preferences`. Missing/invalid `topics` -> 400 ("invalid topic name"/"no valid topics specified"). Mapping tables: `opsFeedEventTopics`, `stateFeedEventTopics`.
- Per-connection buffer `DefaultEventFeedDepth = 1000`; slow client is disconnected ("Client is unable to keep up"). Write timeout defaults to one slot duration; keepalive defaults to the write timeout. Global `--api-timeout` does not apply (handler bypasses `TimeoutHandler`).
- `payload_attributes` and similar fire only when synced (`blockchain/execution_engine.go` `firePayloadAttributesEvent`).

## 4. Engine API client (`beacon-chain/execution/`)
- Methods in `engine_jsonrpc.go`: `NewPayload` (V1 bellatrix, V2 capella, V3 deneb, V4 electra/fulu with requests, V5 gloas), `ForkchoiceUpdated` (V1/V2/V3, V4 gloas), `GetPayload` (V1..V5, V6 gloas; chosen by slot epoch in `getPayloadMethodAndMessage`), `GetBlobs`/`GetBlobsV2`/`GetBlobsV3`/`HasBlobs`, `engine_getPayloadBodiesByHash/Range V1/V2` (`payload_body.go`, used by `ReconstructFullBlock` in `engine_client.go`), `ExchangeCapabilities` (on every (re)connect; result cached), `GetClientVersionV1`; plus `eth_getBlockByHash/Number`.
- Timeouts: `newPayload` and `forkchoiceUpdated` use `ExecutionEngineTimeoutValue` = 8 s (`config/params/mainnet_config.go`); `getPayload` and others `defaultEngineTimeout` = 1 s, Gloas `getPayloadV6` 300 ms (`gloasGetPayloadTimeout`). `getBlobs*` use the caller's ctx. No per-call retry; retries are at the connection level: `pollConnectionStatus` in `rpc_connection.go` re-dials every `backOffPeriod` = 15 s and fails over to the next endpoint if several are configured.
- Error mapping `handleRPCError` (`jsonrpc_error.go`): timeout -> `ErrHTTPTimeout`; JSON-RPC codes -32700/-32600/-32601/-32602/-32603/-32000, -38001 unknown payload, -38002 invalid forkchoice state, -38003 invalid payload attributes, -38004 request too large; "401 Unauthorized" -> logs JWT hint.
- Status handling: `NewPayload` returns `ErrAcceptedSyncingPayloadStatus` for ACCEPTED/SYNCING, `ErrInvalidPayloadStatus` (+latestValidHash) for INVALID, `ErrInvalidBlockHashPayloadStatus`, `ErrUnknownPayloadStatus`. `beacon-chain/blockchain/execution_engine.go`: `notifyNewPayload` treats SYNCING/ACCEPTED as optimistic import (returns false,nil), INVALID -> `invalidBlock{ErrInvalidPayload, lastValidHash}` then `pruneInvalidBlock` (forkchoice `SetOptimisticToInvalid`, removes block+descendants, `defaultLatestValidHash` = 0xff..ff when EL gives none); any other error -> `ErrUndefinedExecutionEngineError` (block not imported, logged "Unexpected execution engine error"). `notifyForkchoiceUpdate`: SYNCING -> optimistic head, logged "Called fork choice updated with optimistic block"; INVALID -> prune invalid chain, pick new head and recurse; other errors are only logged and swallowed (returns nil,nil). VALID -> `SetOptimisticToValid`, caches payload ID (`PayloadIDCache`). Gloas blocks skip `notifyNewPayload` (payload arrives in an envelope, `receive_execution_payload_envelope.go`).
- Optimistic mode: `IsOptimistic` / `IsOptimisticForRoot` on `blockchain` (forkchoice optimistic flags). `--startup-optimistic` hidden feature flag. Validator-facing consequence: block production returns 503 while optimistic.
- JWT: `--jwt-secret` (hex 32-byte file; required for HTTP, not for IPC); token is HS256 with `iat` claim = now, made per request via `network/auth.go` (`authorization.Bearer`); `--jwt-id` adds `id` claim; `--execution-headers k=v,...` extra headers; generate with `beacon-chain jwt generate-auth-secret` (`cmd/beacon-chain/jwt/jwt.go`). Endpoint URL may be http(s) or IPC path (`network/endpoint.go` `NewExecutionRPCClient`). Chain ID sanity check `ensureCorrectExecutionChain`.

## 5. Validator client, keymanager, builder/MEV
- VC code: `validator/client/` (`runner.go` slot loop, `propose.go`, `attest.go`, `aggregate.go`, `sync_committee.go`, `registration.go` builder registration, `duties.go`, `doppelganger.go`, `duty_aware_shutdown.go`, `health_monitor.go`). VC to BN transport: gRPC by default (`--beacon-rpc-provider 127.0.0.1:4000`, `--grpc-retries 5`, `--grpc-retry-delay 1s`; code `validator/client/grpc-api`); REST client under `validator/client/beacon-api` enabled by `--enable-beacon-rest-api` (alias `--enable-rest`) or implicitly by `--beacon-rest-api-provider` (default `http://127.0.0.1:3500`, comma list = multi-BN, listens to all event streams).
- Keymanager API (served by the VC on `--http-host/--http-port` 127.0.0.1:7500, routes in `validator/rpc/server.go`): `GET/POST/DELETE /eth/v1/keystores`, `/eth/v1/remotekeys`, `/eth/v1/validator/{pubkey}/{feerecipient|gas_limit|graffiti|builder_config|voluntary_exit}`. Handlers `validator/rpc/handlers_keymanager.go`, `handlers_validator_config.go`. Auth: bearer token from file `auth-token` in the wallet dir or `--keymanager-token-file` (`validator/rpc/intercepter.go` `AuthTokenHandler`: 401 missing header, 400 bad format, 403 wrong token). Web UI/API under `/v2/validator/*` and `/api/v2/validator/*` (also token-gated except `initialize`, `health/`). Keymanagers: `validator/keymanager/{local,derived,remote-web3signer}`; slashing protection DB `validator/db`.
- Builder/MEV (pre-Gloas, relay API): BN flag `--http-mev-relay <url>` (e.g. mev-boost) enables `beacon-chain/builder`; VC must register validators: `--enable-builder` (alias `--enable-validator-registration`) or proposer settings file; `--suggested-gas-limit`; batch size `--validators-registration-batch-size` 200. `--disable-builder-ssz` forces JSON to the relay.
- Block selection: `beacon-chain/rpc/prysm/v1alpha1/validator/proposer_builder.go` `canUseBuilder` = builder configured AND circuit breaker not tripped AND validator registered (`RegistrationByValidatorID`). Circuit breaker `circuitBreakBuilder`: trips if slots since highest received block >= `MaxBuilderConsecutiveMissedSlots` (3) or missed slots in the last epoch >= `MaxBuilderEpochMissedSlots` (5); flags `--max-builder-consecutive-missed-slots`, `--max-builder-epoch-missed-slots`. Fallback is to the local EL payload.
- Value comparison `setExecutionData` in `proposer_bellatrix.go`: use local unless builder bid meets `--min-builder-bid` (Gwei, default 0), exceeds local by `--min-builder-to-local-difference` (default 0), and `builder_value * builder_boost_factor > local_value * (100 + --local-block-value-boost)` (default boost 10, builder_boost_factor default 100, taken from `builder_boost_factor` query param of `ProduceBlockV3`; warns if both are non-default). Withdrawals root mismatch between builder header and local -> local. Builder `getHeader` bounded by `--builder-header-timeout` (default `BuilderProposalDelayTolerance`, only effective up to Fulu); a failed `getHeader` increments `builder_get_payload_miss_count` and uses local. Blinded block submission failure with `ErrBadGateway` is logged as "Optimistically proposed block - builder relay temporarily unavailable" (`proposer.go` `ProposeBeaconBlock`). `skip_mev_boost` request flag skips the builder.
- Gloas (ePBS): builder bids over P2P and builder API (`proposer_bid.go`, `proposer_gloas.go`, `proposer_submit_bid.go`); circuit breaker is per builder failing to reveal the payload: `beacon-chain/blockchain/builder_circuit_breaker.go`, `beacon-chain/cache` `BuilderCircuitBreaker`, flags `--builder-allowed-failures`, `--builder-critical-failures`, `--builder-blacklist-period`, `--builder-critical-blacklist-period`, `--builder-relay-blacklist-period`, `--builder-failure-backoff-period`, `--builder-critical-failed-builders` (self-build fallback), `--builder-bid-timeout`; feature flag `--disable-builder-relay-circuit-breaker`. VC Gloas flags: `--builder-urls`, `--builder-min-bid`, `--builder-boost-factor` (default 100; <100 favors local, 0 always local), `--builder-max-execution-payment`.

## 6. Quirks / deviations
- Blob endpoints on non-supernodes after Fulu return 404 with a flag hint (see above); `blob_sidecars` is deprecated in favor of `/eth/v1/beacon/blobs/{block_id}`.
- State-by-root is limited to the last 8192 head state roots; by-slot beyond that relies on replay or the state-diff archive.
- 415/406 middleware errors are plain text, not the JSON error schema. Accept header: only the first header line is read.
- Pool/publish handlers return 500 for internal propose failures; no 202.
- Health returns 206 while optimistic; `node/syncing` has `el_offline`.
- Block production: v3 rejected from Gloas on ("use v4"), v4 is Gloas only. Missing `randao_reveal` is tolerated only with `skip_randao_verification` (`skipRandaoVerification`).
- `consensus_block_value` header computed in wei from rewards (`getConsensusBlockValue`), falls back to "0" on failure.
- Many legacy routes return 410 (not 404) with a replacement hint; `/eth/v1/builder/states/{state_id}/expected_withdrawals` has none.
- `/prysm/...` endpoints are non-standard; `/prysm/v1/beacon/blobs` POST publishes blobs.
- Hidden/deprecated flags still work (`--dev`, `--holesky`, TTD overrides) per CHANGELOG v7.3.0.
