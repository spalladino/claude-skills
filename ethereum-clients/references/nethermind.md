Capabilities are computed from the FINAL spec of the chain, not the current head.
- Also an SSZ-REST variant of the engine API: `Nethermind.Merge.Plugin/SszRest/` (paths in `SszRestPaths`, middleware `SszMiddleware`); `exchangeCapabilities` advertises both JSON-RPC names and SSZ paths.
- Fork mismatch errors: `MergeErrorCodes` -38001 UnknownPayload, -38002 InvalidForkchoiceState, -38003 InvalidPayloadAttributes, -38004 TooLargeRequest, -38005 UnsupportedFork, -38006 ReorgTooDeep. newPayloadV1 on wrong fork returns -32602 (InvalidParams), V2+ returns -38005 (see `EngineRpcModule.Paris.cs` NewPayload).
- Limits: getPayloadBodies count max 1024 (`PayloadBodiesHandlerHelper.MaxCount`, error -38004); getBlobs max 128 hashes (`GetBlobsHandler*.MaxRequest`, -38004). getBlobsV2 is all-or-nothing (returns empty/null if any blob missing or node not at head). newPayload/FCU run under a single lock with `LockTimeout` 8 s -> error -32016 "Timed out". `Merge.NewPayloadBlockProcessingTimeout` default 7000 ms (hidden); timeout => returns SYNCING. newPayload returns SYNCING for pre-pivot blocks, unknown parent, still-processing parent.
- Auth: JWT HS256, 32-byte hex secret in file `JsonRpc.JwtSecretFile`; if unset, `StartRpc.ConfigureJwtSecret` uses `<keystore dir>/jwt-secret` (auto-generated; older `keystore/jwt-secret` migrated). Token `iat` TTL 60 s (`Nethermind.Core/Authentication/JwtAuthentication.cs`). `JsonRpc.UnsecureDevNoRpcAuthentication` disables it. Only URLs flagged authenticated (engine URL) require JWT; failure => HTTP 401 `{"error":{"code":-32600,"message":"Authentication error"}}`. Authenticated requests skip batch-size and log-count limits.
- Ports: `JsonRpc.EnginePort` default **null** (no dedicated engine URL); `EngineHost` 127.0.0.1. In practice network presets expose 8551 via `AdditionalRpcUrls: ["http://localhost:8551|http;ws|net;eth;subscribe;engine;web3;client"]` (e.g. `configs/mainnet.json`), Docker `EXPOSE 8545 8551`. Setting `EnginePort` makes the engine URL and ignores additional URLs with engine. Max engine request body 128 MiB (`SocketClient.MAX_REQUEST_BODY_SIZE_FOR_ENGINE_API`) vs 30 MB for public (`MaxRequestBodySize` 30000000). Hosts allowed: `EngineAllowedHosts` `*`.
- GC tuning around newPayload: `Merge.PrioritizeBlockLatency` true, `SweepMemory` Gen1.

## 4. Behaviour reference
### Error codes and messages
- `ErrorCodes.Default`/`ResourceNotFound`/`InvalidInput`/`ExecutionError`/`TransactionRejected` are ALL -32000 (so "header not found", "filter not found", tx rejections, input errors share -32000). Others: -32700 parse, -32600 invalid request, -32601 method not found (`the method X does not exist/is not available`), -32602 invalid params, -32603 internal, -32005 LimitExceeded ("Too many requests", "Batch size limit exceeded"), -32016 Timeout ("Request was canceled due to enabled timeout."), -32017 ModuleTimeout, -32002 ResourceUnavailable, -32001 StandardResourceNotFound (used by `eth_getBlockAccessList` family), -32015 VMError, -32020 AccountLocked, -39001 UnknownBlockError ("Unknown block error" for unresolvable `safe`/`finalized`), 4444 PrunedHistoryUnavailable ("Pruned history unavailable"), 4445 UnavailableBeforeFork, 4 TxSyncTimeout (EIP-7966), 3 ExecutionReverted.
- simulate/trace-spec codes (`ErrorCodes.cs`): -38010 nonce too low, -38011 nonce too high, -38012 fee cap below base fee, -38013 intrinsic gas, -38014 insufficient funds, -38015 block gas limit, -38020 blocks out of order, -38021 timestamp not increased, -38022 movePrecompile self ref, -38024 sender not EOA, -38025 max initcode, -38026 client limit exceeded.
- Header/block lookup: `Modules/BlockFinderExtensions.cs`: `header not found` (-32000), `block body not found`, `requested block range is in the future` (-32602), `<hash> block is not canonical` (requireCanonical). Pruned block (below `LowestServedBlock`) => 4444 "Pruned history unavailable for block X".
- State not available (pruned/unsynced state): `No state available for block <number (hash)>` code -32002 (`EthRpcModule.GetStateFailureResult`, `TxExecutor.Execute`); `missing trie node ... is not available` (-32000) for getStorageAt-like paths.
- Revert: eth_call/estimateGas => error code **3**, message `execution reverted` or `execution reverted: <reason>` (only for Error(string)/Panic selectors; `TransactionSubstate.BuildRevertMessage`), `error.data` = revert hex (`EthRpcModule.TransactionExecutor.cs` `CreateResultWrapper`). Non-revert eth_call failure (-32000) is wrapped geth-style `err: <inner> (supplied gas N)`; estimate: `failed with N gas: <inner>`; createAccessList: `failed to apply transaction: <hash> err: ...` (`Modules/Eth/ErrorWrapper.cs`).
- Tx pool/send errors come from `AcceptTxResult.ToString()` as the message with -32000 (strings in `Nethermind.TxPool/TxPoolErrorMessages.cs` and `Nethermind.Core/Messages/TxErrorMessages.cs`): `already known`, `nonce too low`, `nonce too high` (gap), `nonce too far in future`, `transaction underpriced`, `replacement transaction underpriced`, `insufficient funds for gas * price + value`, `intrinsic gas too low`, `gas limit reached`, `transaction too large`, `sender not an eoa`, `pending transaction type conflict`, `unsupported transaction type`, `delegation nonce gap`, `delegation authority has pending transaction`, `node is syncing`, `Invalid RLP.`. In `eth_call`/trace (EVM-level) nonce errors read `nonce too low: address X, tx: N state: M` (`TransactionProcessor.cs`). Signing without unlocked key: -32020 "authentication needed: password or unlock".

### eth_call / eth_estimateGas
- `JsonRpc.GasCap` default 100_000_000 (null or 0 = uncapped, `Nethermind.Core/GasCapExtensions.cs`). Requested gas above cap is clamped for call (`ToCallTransaction(..., _rpcConfig.GasCap)`); `blockOverrides.gasLimit` above cap => -32000 `GasLimit value is too large, max value N`. Also EIP-7825 per-tx cap (2^24) applied in estimate when active and EIP-8037 not.
- Estimate algorithm: `Nethermind.Blockchain/Tracing/GasEstimator.cs`: caps `hi` by sender balance/feeCap allowance, plain-transfer fast path (21000), probe run at `hi`, optimistic guess `(peakGas + 2300) * 64/63`, then binary search until within `JsonRpc.EstimateErrorMargin` (default **150 bps = 1.5%**; so result can exceed the minimal gas by up to 1.5%; margin >= 10000 rejected). Errors: `gas required exceeds allowance (N)`, `insufficient funds for transfer`, `execution reverted` (+ data). Execution: `Nethermind.Facade/BlockchainBridge.cs` (`Call`, `EstimateGas`).
- Overrides: state overrides (`state` XOR `stateDiff`, else `account X has both 'state' and 'stateDiff'`; `Modules/StateOverrideValidation.cs`), block overrides (`beaconRoot` and `withdrawals` unsupported => error; `BlockchainBridge.GetUnsupportedBlockOverrideError`), blob base fee override. Calls with overrides take the exclusive env pool (cap `EthModuleConcurrentInstances`, else -32005); plain calls use shared singleton handler (`MaxConcurrentSharedRequests` 10000). Block param `pending` runs on head (see tags). Fee-default rules: `Modules/Eth/FeeDefaultRules.cs`.
- Concurrency/timeouts: per-request timeout `JsonRpc.Timeout` 20000 ms (cancellation => -32016); batch of eth_call/estimate/createAccessList executes `BatchProcessingConcurrency` (4) at once (`EthCallBatchConcurrency.cs`).

### eth_getLogs / filters
- `EthRpcModule.GetLogs` -> `BlockchainBridge.GetLogs` -> `Nethermind.Facade/Find/LogFinder.cs`. **No block-range limit** (only `MaxBlockRange` equivalent is `OverlayMaxBlockRange` 1000 for `overlay_getLogs`). Limits: `JsonRpc.MaxLogsPerResponse` 20000 (0 = off; error -32005 `Too many logs requested. Max logs per response is 20000.`; not enforced for authenticated callers); `JsonRpc.Timeout` 20 s; `RequestQueueLimit` 500 + `EthModuleConcurrentInstances` (non-sharable queue; overflow => HTTP 503). Optional streaming (`EnableLogsStreamMode` false, `MaxLogsResponseBodySize`): truncates instead of erroring. Bad ranges: from>to => -32602 `invalid block range params`; range past head => -32602 `requested block range is in the future`; blockHash + from/to => `cannot specify both BlockHash and FromBlock/ToBlock, choose one or the other`. Missing/pruned receipts => 4444 `Pruned history unavailable` (or -32000 if just not processed). `logIndex` (`LogIndex.Enabled`) can accelerate (`filter.UseIndex`).
- Filters (`eth_newFilter` etc.): `Nethermind.Facade/Filters/FilterStore.cs`, `FilterManager.cs`; expire after `JsonRpc.FiltersTimeout` 900000 ms; unknown id => -32000 `filter not found`.

### Block tags
- Resolution: `Nethermind.Blockchain/Find/IBlockFinder.cs` (`FindHeader/FindBlock(BlockParameter)`), `BlockParameter.cs` (parsing; `JsonRpc.StrictHexFormat` true = strict block params/hashes). `latest` = `BlockTree.Head`; `earliest` = genesis (`FindGenesisHeader`); `finalized`/`safe` = `FinalizedHash`/`SafeHash` set by `engine_forkchoiceUpdated` (null until first FCU => not found: -39001 "Unknown block error" on block lookups, `header not found` on header lookups); `requireCanonical` supported.
- **`pending` = head**: `BlockTree.PendingHash => Head?.Hash`. Differences: `eth_getTransactionCount(pending)` uses txpool (`_txPool.GetLatestPendingNonce`); `eth_getBlockByNumber(pending)` returns head block with `hash/nonce/miner` nulled; `eth_getHeaderByNumber(pending)` returns null (execution-apis#877); `eth_getBlockAccessList` pending special-cased. No locally built pending block (no txpool-included state) for calls/balances.

### Gas price / fee history
- `eth_gasPrice`: `Modules/Eth/GasPrice/GasPriceOracle.cs`: 60th percentile (`PercentileOfSortedTxs`) of effective prices from last 20 blocks (`DefaultBlocksLimit`), max 3 txs per block, ignore < 2 wei, cap 500 gwei (`MaxGasPrice`), fallback `(MinGasPrice + baseFee) * 110/100`; cached per head hash. `eth_maxPriorityFeePerGas`: same percentile over last 100 blocks of priority fees, fallback 200 gwei with no head. Constants in `EthGasPriceConstants.cs`.
- `eth_feeHistory`: `FeeHistory/FeeHistoryOracle.cs`: `blockCount` clamped to 1024 (not an error), `blockCount < 1` => -32602, max 100 percentiles, must be strictly increasing within 0..100, `request beyond head block` (-32000), pruned => 4444.

### eth_sendRawTransaction / txpool
- Flow: `EthRpcModule.eth_sendRawTransaction` (RLP decode; `Invalid RLP.` -32000) -> `SendTx` with `TxHandlingOptions.PersistentBroadcast` -> `Nethermind.TxPool/TxPoolSender.cs` -> `TxPool.SubmitTx` -> ordered `IIncomingTxFilter`s in `Nethermind.TxPool/Filters/`. Returns hash or -32000 + AcceptTxResult text. **No fee cap on sendRawTransaction**: `JsonRpc.RpcTxFeeCap` (1 ETH default) is applied only in `eth_signTransaction` (`CheckTxFeeCap`); `eth_signTransaction` itself disabled by default (`EnableEthSignTransaction`). `eth_sendRawTransactionSync`: default wait `RpcTxSyncDefaultTimeoutMs` 20000, max 60000, concurrency `RpcTxSyncMaxConcurrentRequests` 128, timeout error code 4.
- RPC-submitted (local, PersistentBroadcast) txs **bypass** `FeeTooLowFilter` and the nonce-gap filter (gaps allowed locally); P2P txs face them. `GapNonceFilter` for remote txs: gaps allowed only while pool not full; blob txs never allowed a gap beyond `nonce <= current + pending count`.
- Config (`ITxPoolConfig`, defaults in `TxPoolConfig.cs`): `Size` 2048 (standard pool); `MaxPendingTxsPerSender` 0 (unlimited); `MaxPendingBlobTxsPerSender` 16; `MaxTxSize` 131072 B; `MaxBlobTxSize` 1 MiB (excl. blobs); `GasLimit` null; `MinBaseFeeThreshold` 70 (% of base fee for broadcast); `HashCacheSize` 131072; `AcceptTxWhenNotSynced` false (=> `node is syncing`); `PersistentBroadcastEnabled` true.
- Replacement price bump: `Comparison/CompareReplacedTxByFee.cs`: new tx needs **>= +10%** on both maxFeePerGas and maxPriorityFeePerGas (legacy: gasPrice +10%); zero-fee old txs always replaceable; exact-boundary accepted only if the bump is nonzero. Otherwise `replacement transaction underpriced`. Blob txs: `CompareReplacedBlobTx.cs`: **2x** on maxFee, maxPriorityFee and maxFeePerBlobGas, no fewer blobs than the old tx; always replaceable by a higher blob-proof wrapper version (cell proofs).
- Blob (type 3): separate pool (`TxPool.Blobs.cs`, `BlobTxStorage.cs`); `BlobsSupport` default `StorageWithReorgs` (modes Disabled/InMemory/Storage/StorageWithReorgs); `PersistentBlobStorageSize` 16384 txs, `BlobCacheSize` 256, `InMemoryBlobPoolSize` 512; `CurrentBlobBaseFeeRequired` true (maxFeePerBlobGas >= current blob base fee), `MinBlobTxPriorityFee` 0; `ProofsTranslationEnabled` false (v0 <-> v1 proof conversion); a sender cannot mix blob and non-blob pending txs (`TxTypeTxFilter` => `pending transaction type conflict`); blob txs must arrive with full network wrapper (`BlobProofsTxFilter`, `incomplete blob data`/`invalid blob proofs`). Max blobs per tx: `ReleaseSpec.MaxBlobsPerTx` (EIP-7594 cap).
- Set-code (type 4, EIP-7702): `Filters/DelegatedAccountFilter.cs`: if the sender is delegated (or has a pending delegation) only the next nonce is accepted (`delegation nonce gap`); a tx whose authorization list names an authority that has pending txs is rejected (`delegation authority has pending transaction`). `RecoverAuthorityFilter` runs first. EIP-8141 frame-tx/keyed-nonce rules also present (many `FrameTx*` config items, off the beaten path).
- `txpool_*` RPC: `TxPool/TxPoolRpcModule.cs`; pending view: `TxPoolInfoProvider`.

### Batches, sizes, WS
- `JsonRpc.MaxBatchSize` 1024 requests (`JsonRpcProcessor`: -32005 `Batch size limit exceeded`); `MaxBatchResponseBodySize` 33554432 B (error `MaxBatchResponseBodySize of NKB exceeded`); `MaxRequestBodySize` 30000000 B (HTTP 413 + -32005 `Request body too large...`; same for WS messages); `JsonSerializationMaxDepth` 4096; `BufferResponses` false (chunked); `MaxJsonStringArgLength` 1M chars (`JsonRpcLimits.cs`). Batch/log limits apply only to unauthenticated contexts. WS pipelined concurrency `WebSocketsProcessingConcurrency` 16 (out-of-order responses; set 1 for strict order), IPC `IpcProcessingConcurrency` 16. CORS `CorsOrigins` `*`; WS handshake with Origin not in list => HTTP 403.
- Subscriptions (`Modules/Subscribe/SubscriptionType.cs`): `eth_subscribe` types `newHeads`, `logs`, `newPendingTransactions`, `droppedPendingTransactions`, `syncing`, `transactionReceipts`; `admin_subscribe` `peerEvents`. Unsub unknown id => -32000 `subscription not found`. Subscribe module is a bounded pool of 2 instances. Per-connection max subscription count: unverified.
- No generic per-IP rate limiting in the node; the only throttles are the concurrency/timeouts above (`MaxConcurrentSharedRequests`, `RequestQueueLimit`, module pool sizes, `Debug/TraceModuleConcurrentInstances`, `TraceBlockParallelism` 4). Overload => HTTP 503 and/or -32005 "Too many requests".

### eth_simulateV1
- `Modules/Eth/SimulateTxExecutor.cs` + `Nethermind.Facade/Simulate/SimulateBridgeHelper.cs`. Max blocks `JsonRpc.MaxSimulateBlocksCap` 256 (error -38026 `This node is configured to support only 256 blocks`/`too many blocks`). Total gas across all simulated blocks/calls is shared and bounded by `GasCap` (`TotalGasLeft`). Error codes -38010..-38026 as above; empty `blockStateCalls` => -32602. `validation:true` enables fee/nonce validation. Trace variants: `debug_simulateV1`, `trace_simulateV1`. ### Tracing
- debug (geth style): tracers registered in `Nethermind.Blockchain/Tracing/GethStyle/Custom/Native/GethLikeNativeTracerFactory.cs`: native `callTracer`, `prestateTracer`, `4byteTracer`, `noopTracer`, `keccak256PreimageTracer`, `stateGasTracer`, plus `muxTracer` (`Nethermind.Consensus/Tracing/GethLikeBlockMuxTracer.cs`); JavaScript tracers via ClearScript V8 (`Custom/JavaScript/`); default (no tracer) = struct logger. - Config: `EnableTracingStreamMode` true; `MaxBufferedTraceLogSize` 268435456 B; `DebugModuleConcurrentInstances` (default CPUs capped at 16), `TraceModuleConcurrentInstances` default 2 (over cap => -32005 LimitExceeded).

### History / state pruning
- State: `Pruning.Mode` Hybrid (in-memory + full pruning options: `FullPruningTrigger`, `FullPruningThresholdMb`...), in-memory boundary `PruningBoundary` 64 blocks; older non-archive state => `No state available for block ...` (-32002) for calls/balances/proofs. Flat DB history (archive-style queries): `FlatDb.HistoryEnabled` false, `HistoryRetention` None/Rolling/SinceBlock, `HistoryRetentionBlocks`, `HistoryTransactionIndexEnabled` (e.g. `configs/mainnet_aztec.json` uses Rolling 4096 blocks). Archive presets: `configs/*_archive.json`.
- Block/receipt history: `History.Pruning` default `Disabled` (modes Rolling, UseAncientBarriers); `History.RetentionEpochs` null => chainspec `minHistoryRetentionEpochs` (33024 mainnet = ~1 year, EIP-4444 style; 14299 sepolia); `BalRetentionEpochs`; `PruningInterval` 8 epochs, `PruningTimeoutSeconds` 2 (`Nethermind.History/IHistoryConfig.cs`). Sync side: `Sync.AncientBodiesBarrier/AncientReceiptsBarrier` (mainnet preset 24600000), `DownloadReceiptsInFastSync` true. Pruned/unsynced history => 4444 `Pruned history unavailable`; blocks/receipts not yet backfilled report via `SyncMode.HaveNotSyncedReceiptsYet`.

## 5. Quirks / deviations
- Most failures share -32000 (not -32602 / -32001); revert is code 3 like geth; many geth-style message strings are intentionally copied (`ErrorWrapper.cs`), but nethermind-specific ones exist (`delegation nonce gap`, `pending transaction type conflict`).
- `pending` == `latest` for state/block reads (no pending-state); only nonce uses txpool.
- `eth_getLogs` has no block-range cap (only result count 20000 and 20 s timeout), unlike geth/erigon/reth configs that cap ranges; hitting the limit errors out unless `EnableLogsStreamMode` (then silently truncated per streaming rules).
- `JsonRpc.Enabled` default false in code but true in all shipped presets; engine port default null (8551 via preset `AdditionalRpcUrls`); `debug`, `admin`, `personal` off by default.
- Estimate gas returns within 1.5% of the true minimum by default (`EstimateErrorMargin` 150 bps) - values may differ from geth's exact bisection.
- `eth_feeHistory` clamps blockCount to 1024 instead of erroring; header methods return null for pending.
- RPC-submitted txs skip underpriced/gap pool filters; no 1 ETH tx-fee cap on raw sends.
- Replacement bump is 10% on both fee fields (geth also 10%); blob replacement 2x on all three fees (geth requires fewer).
- Engine: very new versions (newPayloadV6/FOCIL, fcuV5, getBlobsV4, SSZ-REST) exist on master; capabilities derived from final chain spec.
- JSON-RPC `StrictHexFormat` true: stricter hex parsing than other clients.
