# Besu (execution)

Java (Gradle multi-module, Vert.x HTTP/WS, picocli CLI). GitHub: https://github.com/besu-eth/besu (formerly hyperledger/besu). Local: `~/Projects/ethereum/besu` (blobless partial clone), default branch `main`.
Latest release: calendar versions `YY.M.patch` (26.11.0 = Oct 30 2026; RCs like `26.7.0-RC1`). Tags come in pairs: `26.11.0` and `main-rel-v26.11.0`. `git tag --sort=-v:refname` is WRONG (puts `main-rel-v*` and junk like `develop`/`canary`/`GHA-TESTRUN-1` first). Use `git tag --sort=-creatordate | grep -E '^[0-9]+\.[0-9]+\.[0-9]+$' | head` or `CHANGELOG.md` headings (`## Unreleased`, then `## 26.11.0`, `## 26.10.2` ...). `main` is ahead of the last tag; `## Unreleased` lists what is only on main. Paths below are relative to repo root. `API` = `ethereum/api/src/main/java/org/hyperledger/besu/ethereum/api`, `JR` = `API/jsonrpc`, `M` = `JR/internal/methods`.

## 3. Engine API
- Handlers: `M/engine/` ; registration + fork scheduling: `JR/methods/ExecutionEngineJsonRpcMethods.java` (`VersionScheduler`). Per-version classes are a sealed hierarchy (V(N) extends V(N-1)); fork window enforced in `ExecutionEngineJsonRpcMethod` (`validateForkSupported`, `ForkSupportHelper`) -> `-38005 Unsupported fork`. `M/engine/README.md` explains how to add versions. The method set does not depend on the network; fork rules are checked per call.
- Versions on main (activation fork): `engine_newPayload` V1(<Shanghai) V2(Shanghai+) V3(Cancun+) V4(Prague+) V5(Amsterdam+); `engine_newPayloadWithWitnessV5` (Amsterdam; only registered on Bonsai/path-based world state); `engine_forkchoiceUpdated` V1/V2/V3(Cancun)/V4(Amsterdam); `engine_getPayload` V1..V4 (V4 Prague) V5 (Osaka) V6 (Amsterdam); `engine_getPayloadBodiesByHash/ByRange` V1,V2 (always active; max request 1024, `GET_PAYLOAD_BODIES_MAX_REQUEST_SIZE`; too large -> `-38004`); `engine_getBlobsV1` (Cancun+), V2 + V3 (Osaka+, V2 all-or-nothing, V3 partial), V4 (Osaka+, returns cells/proofs); getBlobs max 128 versioned hashes (`REQUEST_MAX_VERSIONED_HASHES`) else `-38004`; `engine_exchangeCapabilities` (built from the registered list); `engine_getClientVersionV1`; `engine_exchangeTransitionConfigurationV1` (only until Cancun / when no merge coordinator).
- Port/auth: `JsonRpcConfiguration.createEngineDefault()`: port 8551, apis `ENGINE,ETH` (only these two namespaces on the engine port), JWT HS256 required, max body 128MB (`DEFAULT_ENGINE_MAX_REQUEST_CONTENT_LENGTH`), host allowlist `localhost,127.0.0.1` (`--engine-host-allowlist`). Options (`EngineRPCOptions`): `--engine-rpc-port`/`--engine-rpc-http-port`, `--engine-jwt-secret <file>` (>=256 bit hex), `--engine-jwt-disabled`, `--engine-rpc-enabled` (otherwise enabled automatically for merge-capable genesis). No secret given -> ephemeral key written to `<datadir>/jwt.hex` (`authentication/EngineAuthService.EPHEMERAL_JWT_FILE`). JWT check: `iat` must be within +/-60s (`JWT_EXPIRATION_TIME_IN_SECONDS = 60`, leeway 5s, `exp` ignored); stale -> 401. WS engine on same 8551.
- Behaviour: newPayload NEVER returns `ACCEPTED` (comment in `EngineNewPayloadV1`: a payload with known parent is always fully validated, side chains too); returns `SYNCING` if parent unknown/needs sync; `INVALID_BLOCK_HASH` on hash mismatch. FCU: `-38002 Invalid forkchoice state`, `-38003 Invalid payload attributes`, `-38006 Too deep reorg` when reorg depth > `MergeMiningCoordinator.MAX_REORG_DEPTH = 90_000` (`consensus/merge/.../MergeMiningCoordinator.java`); FCU to an ancestor of finalized returns VALID without reorg. `EngineQosTimer` warns after 120s without a CL call. Engine methods execute concurrently except newPayload/FCU which extend `OrderedExecutionJsonRpcMethod` (FIFO).
- Request size guard: `--Xrpc-max-request-token-count` default 500,000 JSON tokens (all JSON-RPC/Engine/WS/GraphQL).

## 4. Behaviour reference

### Error codes/messages
- Defined in `JR/internal/response/RpcErrorType.java` (enum: code, message, optional revert-data decoder); wrapped by `JsonRpcError` (`message` becomes `"<msg> (<reason>)"` when a reason/detail exists; `data` carries raw hex for reverts). TransactionInvalidReason -> RpcErrorType mapping: `JR/JsonRpcErrorConverter.java` (enum `ethereum/core/.../transaction/TransactionInvalidReason.java`; unmapped -> `-32603 Internal error`).
- Key ones: execution reverted `3 "Execution reverted"` with `data`=revert hex and reason decoded for `Error(string)`/`Panic(uint)` -> message `Execution reverted (<reason>)` (note: not geth's `execution reverted: reason`); `-32001 Nonce too low`; `-32006 Nonce too high`; `-32002 Invalid signature`; `-32003 Intrinsic gas exceeds gas limit`; `-32004 Upfront gas cost exceeds account balance` / `Insufficient funds for transfer`; `-32005 Transaction gas limit exceeds block gas limit` / `Transaction gas limit cap exceeded` (EIP-7825 cap 16,777,216 on Osaka+) / all `EXCEEDS_RPC_*` limit errors (range, batch, filters, subscriptions, trace limits, filter addresses); `-32007 Sender account not authorized` (permissioning); `-32008 Initial sync is still in progress`; `-32009 Gas price below configured minimum gas price` / `below current base fee` / `blob gas price below current blob base fee`; `-32000 Known transaction`, `-32000 Replacement transaction underpriced`, `-32000 Transaction fee cap exceeded`, `-32000 Transaction size exceeds the maximum allowed size`, `-32000 Wrong chainId`, `-32000 Block not found`, `-32000 World state unavailable`, `-32000 Filter not found`, `-32000 Transaction nonce is too distant from current sender nonce`; `-39001 Unknown block` (finalized/safe unavailable); `4444 Pruned history unavailable`; `-32001 Resource not found`; `-32602 Invalid params` family (`Invalid block param (block not found)` etc.); `-32603 Timeout expired`; `-32700/-32600/-32601` standard; `-40100 Unauthorized`; engine `-38001..-38006`.
- Block-state-call (eth_simulateV1) errors are separate: `ethereum/core/.../transaction/exceptions/BlockStateCallError.java` (-38010 nonce too low, -38011 nonce too high, -38012 BaseFeePerGas too low, -38013 intrinsic gas, -38014 upfront cost exceeds balance, -38015 gas exceeds block limit, -38020/-38021 block numbers/timestamps not ascending, -38022 precompile move to self, -38023 duplicate move target, -38026 too many block calls).
- Missing-block behaviour: methods based on `AbstractBlockParameterOrBlockHashMethod` return `null` (success) for unknown hash or future block number; eth_call / eth_simulateV1 override to `-32000 Block not found`; `eth_getLogs` by unknown blockHash -> `Block not found` error.

### Block tags (`JR/internal/parameters/BlockParameter`, `BlockParameterOrBlockHash`; resolution in `M/AbstractBlockParameterMethod` and `M/AbstractBlockParameterOrBlockHashMethod`)
- `latest`, `earliest` (=0), `safe`, `finalized`, `pending`, hex number (must have `0x`, else IllegalArgument -> -32602), or `{blockHash, requireCanonical}` / `{blockNumber}` objects. `safe`/`finalized` come from the CL via FCU; before any FCU they resolve to nothing -> `-39001 Unknown block` (`BlockchainQueries.safeBlockHeader/finalizedBlockHeader`).
- `pending` generally == `latest` (comments: "Pending not implemented, returns latest"; default `pendingResult()` returns latest). Exceptions: `eth_getTransactionCount(pending)` = max(txpool next nonce for sender, latest nonce) (`EthGetTransactionCount.pendingResult`, via `TransactionPool.getNextNonceForSender`); `eth_estimateGas` / `eth_createAccessList` with `pending` (and **estimateGas defaults to `pending` when the block param is omitted**) simulate on a synthetic pending header (`TransactionSimulator.simulatePendingBlockHeader`).
- Quirks: `eth_call` REQUIRES the block parameter (`EthCall.blockParameterOrBlockHash` uses `getRequiredParameter(1)` -> `-32602 Invalid block or block hash parameters (index 1)` if omitted), whereas eth_getBalance/getTransactionCount/eth_simulateV1 default to `latest`. `eth_feeHistory` treats `latest/pending/safe/finalized` all as chain head (only numeric/earliest give a number; `EthFeeHistory`).

### eth_call / eth_estimateGas / eth_createAccessList
- `M/EthCall` -> `TransactionSimulator` (`ethereum/core/.../transaction/TransactionSimulator.java`). State overrides: param index 2 (`StateOverrideMap`: balance, nonce, code, state, stateDiff, movePrecompileToAddress). **Block overrides (param 3) are NOT implemented in eth_call** (`// TODO implement for block overrides` in `EthCall`); they exist in eth_simulateV1. Blob-related: `CallParameterUtil.rejectBlobFieldsWithoutHashes`.
- Gas cap `--rpc-gas-cap` default `100_000_000` (`ApiConfiguration.DEFAULT_GAS_CAP`; 0 = no limit). `TransactionSimulator.calculateSimulationGasCap`: user gas > cap -> cap; no user gas -> min(cap, block gas limit). `strict` flag (`CallParameter.strict`, default true) controls balance checking; non-strict allows exceeding balance (`getTransactionValidationParams`).
- Revert: eth_call error `3` + `data` hex (see above). eth_estimateGas also returns the revert error if the max-gas run fails.
- estimateGas algorithm (`M/EthEstimateGas`, base `M/AbstractEstimateGas`): upper bound = min(block gas limit, tx gas cap (EIP-7825), and sender balance / maxGasPrice when strict and sender known); if plain value transfer try `minTxCost` (intrinsic) first; run at upper bound; take gas used; optimistic second run at `(used + 2300 stipend) * 64/63`; then binary search with early exit when `(high-low)/high < --estimate-gas-tolerance-ratio` (default **0.015**; 0 = exact). Result may therefore be up to ~1.5% above the true minimum. Upper bound below min tx cost -> `-32004 Upfront gas cost exceeds account balance`.

### eth_getLogs (`M/EthGetLogs`, `JR/internal/parameters/FilterParameter`)
- `--rpc-max-logs-range` default **5000** blocks (0 = unlimited): error `-32005 "Requested range exceeds maximum RPC range limit"` with `data` = the limit; note check is `(to - from) > max`, i.e. up to 5001 blocks pass. **No result-count limit** in code. Address list cap `--rpc-max-log-filter-addresses` default 1000 (`-32005 Filter address count exceeds limit`; also eth_newFilter/eth_subscribe/GraphQL). `fromBlock > toBlock` or `toBlock > head` -> `-32602 Invalid params` (not geth's empty result; `FilterParameter.validateBlockRange`). `fromBlock/toBlock` of `safe/finalized` unavailable -> `-32602 "... not found"`. Request aborts if client disconnects (`requestContext::isAlive`) and under the HTTP timeout. Pruned-bodies behaviour for logs: unverified (see section on pruning). GraphQL has `--graphql-max-blocks-range`.

### Gas price oracle / feeHistory
- `eth_gasPrice` (`M/EthGasPrice` -> `BlockchainQueries.gasPrice`): percentile (`--api-gas-price-percentile` 50) of tx prices over last `--api-gas-price-blocks` (default **100**; 0 = disabled -> lower bound), clamped to [lower bound, `--api-gas-price-max` 500 gwei]; lower bound = max(`--min-gas-price`, next-block base fee). Sampling is cached per chain-head hash. Note: the sample uses `Transaction.getGasPrice()` (present for legacy/2930 txs); 1559 txs contribute via priority fee for `eth_maxPriorityFeePerGas` (`gasPriorityFee`, floor `--min-priority-fee`) - verify exact sampling before relying on it. Optional bounding: `--api-gas-and-priority-fee-limiting-enabled` (+ lower/upper coefficient, percent of lower bound).
- `eth_feeHistory` (`M/EthFeeHistory`): blockCount 1..1024 (else `-32602 Invalid block count params`), up to 100 reward percentiles, must be strictly ascending in [0,100]; newestBlock > head -> `-32602 Invalid block number params`; returns baseFee for next block, `baseFeePerBlobGas`, `blobGasUsedRatio`; memory-bound caches (32MB per-block rewards, 16MB results for `latest` requests).
- `eth_blobBaseFee`: `M/EthBlobBaseFee`.

### eth_sendRawTransaction / txpool
- `M/EthSendRawTransaction`: exactly 1 param (`-32602 Invalid number of params`); decode via `DomainObjectDecodeUtils.decodeRawTransaction`; RLP decode failure returns **`-32602 "Invalid block param (block not found)"`** (misleading INVALID_BLOCK_PARAMS, quirk); then `TransactionPool.addTransactionViaApi` (`ethereum/eth/.../transactions/TransactionPool.java`, `validateTransaction`, `validatePrice`) -> errors mapped via `JsonRpcErrorConverter`. Order of checks: already-known (`Known transaction`), max tx size, fee cap, min gas price, `MainnetTransactionValidator` (`ethereum/core/.../mainnet/`), strict replay protection, block gas limit, blob must have >=1 blob, plugin validator, sender-state validation (nonce too low, balance).
- Fee cap: `--rpc-tx-feecap` default **1 ETH** (`DEFAULT_RPC_TX_FEE_CAP = Wei.fromEth(1)`); compared against the tx max gas price (`getMaxGasPrice`; not multiplied by gas limit in `validatePrice`, so it caps the per-gas price - verify) (per CHANGELOG "Upcoming": value 0 currently means no cap, will change). P2P: `--p2p-tx-feecap` default unlimited. Strict EIP-155: `--strict-tx-replay-protection-enabled` false by default (RPC only).
- Implementations: `--tx-pool` = `LAYERED` (default, `ethereum/eth/.../transactions/layered/*`: prioritized -> ready -> sparse layers) | `SEQUENCED`/`LEGACY` (synonyms; legacy pool is being removed). `TransactionPoolConfiguration` defaults: `--tx-pool-max-size` 4096 (legacy/sequenced only), layered: `--tx-pool-layer-max-capacity` 75 MB per layer, `--tx-pool-max-prioritized` 10000, `--tx-pool-max-prioritized-by-type` BLOB=21, `--tx-pool-max-future-by-sender` **200** (nonce gap tolerated up to 200 ahead; else `NONCE_TOO_FAR_IN_FUTURE_FOR_SENDER`; `LayeredPendingTransactions`), `--tx-pool-min-score` -128, `--tx-pool-enable-balance-check` true, legacy `--tx-pool-limit-by-account-percentage` 0.001, retention `--tx-pool-retention-hours` 13 (or `--tx-pool-retention-seconds`), `--tx-pool-min-gas-price` **1000 wei**, `--tx-pool-max-tx-bytes` **131072** (128 KiB, excludes blobs), save/restore `--tx-pool-enable-save-restore` false (`txpool.dump`), `--tx-pool-no-local-priority` false (RPC senders get priority), `--tx-pool-priority-senders`.
- Replacement: `--tx-pool-price-bump` default **10%**; `--tx-pool-blob-price-bump` default **100%** (blob replacement requires maxFeePerBlobGas >= 2x). Rule: `TransactionReplacementByFeeMarketRule` (effective price must be bumped by %, and effective priority fee not lower; if equal price, priority bumped); same nonce, otherwise `-32000 Replacement transaction underpriced`. Blob tx can only replace/be replaced by blob tx. Legacy gas-price chains use `TransactionReplacementByGasPriceRule`.
- Blob (type 3): needs >=1 blob; blob fee must cover current blob base fee for pool admission (`BLOB_GAS_PRICE_BELOW_CURRENT_BLOB_BASE_FEE`); max blobs per tx on Osaka+ default 6 (`OsakaTargetingGasLimitCalculator.DEFAULT_MAX_BLOBS_PER_TRANSACTION`, override `--max-blobs-per-transaction`, `--max-blobs-per-block`); Osaka upgrades a locally submitted v0 blob wrapper to v1 cell proofs in the pool (`TransactionPool` pre-processor). Blobs cached in `BlobCache`.
- Set-code (type 4, EIP-7702): `ethereum/eth/.../transactions/DelegationLimits.java` (applied only for layered pool, `requiresDelegationLimits`): an account that is delegated (or about to be via a pending authorization) may have only ONE pending tx (its current nonce); errors `DELEGATION_AUTHORITY_HAS_PENDING_TRANSACTIONS`, `NONCE_ALREADY_CONSUMED_FOR_SENDER`; excess queues purged when a delegation lands in a block. Authorities are recovered before taking the pool lock.
- txpool_* RPCs: Besu-specific `txpool_besu*`; standard `txpool_status/content/contentFrom/inspect`. Txpool disabled (e.g. `--tx-pool` off / still syncing) -> `TX_POOL_DISABLED` "Transaction pool not enabled...".

### Batch / size / timeouts / rate limits
- Batch: `--rpc-http-max-batch-size` default **1024** (0 = none), over -> `-32005 Number of requests exceeds max batch size` (`JsonRpcArrayExecutor`); empty batch -> parse error; non-object entries -> `-32600`. Batch is executed sequentially and streamed back (`JsonResponseStreamer`); notifications produce no entry. No response-size limit in code (responses are streamed with backpressure `StreamBackpressure`); request body limit `--rpc-http-max-request-content-length` 10 MiB (engine 128 MiB).
- Timeouts: `--Xhttp-timeout-seconds` default **30** -> HTTP 504 (`TimeoutOptions`, `TimeoutHandler`; also closes connection; already-streaming responses are reset); streaming methods (`debug_traceBlock*`, `trace_*` streaming) `--Xhttp-streaming-timeout-seconds` 600; `--Xws-timeout-seconds` 30. In-method timeout error: `-32603 Timeout expired`.
- Connections: `--rpc-http-max-active-connections` 80; WS `--rpc-ws-max-active-connections` 80, `--rpc-ws-max-frame-size` 1 MiB, `--rpc-ws-max-active-subscriptions` 100,000. No per-IP rate limiting in Besu.
- Auth (non-engine): `--rpc-http-authentication-enabled`, credentials TOML or JWT public key; `/login` endpoint; `--rpc-http-api-methods-no-auth`.

### WS subscriptions
- `eth_subscribe` types (`websocket/subscription/request/SubscriptionType`): `newHeads`, `logs`, `newPendingTransactions`, `droppedPendingTransactions`, `syncing`, `transactionReceipts`; `eth_unsubscribe`. Exceeding max -> `-32005 Maximum number of active subscriptions exceeded`. Log subscriptions share the address cap. Handlers `websocket/subscription/{blockheaders,logs,pending,syncing,transactionreceipts}` + `SubscriptionManager`.

### eth_simulateV1 (`M/EthSimulateV1` -> `ethereum/core/.../transaction/BlockSimulator`, `BlockStateCalls`, params `JR/internal/parameters/SimulateV1Parameter`)
- Block param defaults `latest`; max block span `MAX_BLOCK_CALL_SIZE = 256` beyond header (`-38026 Too many block calls`); fills gap blocks; supports `validation`, `traceTransfers`, `returnFullTransactions`, block/state overrides, `movePrecompileToAddress` (invalid -> `-32000`/`-38022`/`-38023`), plugin-provided block-import tracing (`traceBlockImport`). Total gas bounded by `--rpc-gas-cap` across the whole simulation (`BlockSimulator.remainingGasCap`). On Amsterdam `maxUsedGas` = max(execGas+stateGas, calldata floor) (CHANGELOG Unreleased).

### debug_trace* / trace_*
- Tracers (`ethereum/core/.../debug/TracerType.java`): default opcode (struct logger) tracer, `callTracer`, `flatCallTracer`, `prestateTracer` (diffMode/disableCode/disableStorage/includeEmpty), `4byteTracer`. Result classes: `JR/internal/results/{calltrace,prestate,...}`; config `JR/internal/parameters/TransactionTraceParams`. JS tracers (custom `tracer: "<js>"`) not supported (verify).
- Limits: `--rpc-max-trace-steps` default 1,000,000 EVM steps per trace (`DEBUG_TRACE_STEP_LIMIT`, `TraceStepLimit`); `debug_traceBlock*` rejects blocks with > 300 txs (`MAX_TRACE_BLOCK_TX_COUNT`, `EXCEEDS_RPC_TRACE_BLOCK_TX_COUNT`) or block gas limit > 50,000,000 (`MAX_TRACE_BLOCK_GAS_LIMIT`) (constants in `M/DebugTraceBlock.java`; check `AbstractDebugTraceBlock`/`DebugTraceBlockByNumber` for whether they apply equally - unverified); `trace_filter` `--rpc-max-trace-filter-range` default 1000 blocks; trace_filter has `PRUNED_HISTORY_UNAVAILABLE` and strict param validation (CHANGELOG Unreleased). Genesis not traceable (`-32000 genesis is not traceable`). Tracing needs historical world state (Bonsai limit below) else `-32000 World state unavailable`.
- Debug/trace namespaces are not enabled by default (only ETH,NET,WEB3).

### Pruning / history / state
- Default `--data-storage-format` = **BONSAI** (`DataStorageOptions`, FOREST legacy; `X_BONSAI_ARCHIVE` experimental). Bonsai keeps trie logs for `--bonsai-historical-block-limit` default **512** blocks (`ExtraStorageConfiguration.DEFAULT_MAX_LAYERS_TO_LOAD`); `--bonsai-limit-trie-logs-enabled` true; pruning window 5000. Historical state reads (eth_getBalance/getStorageAt/getCode/eth_call/getProof/tracing) beyond ~512 blocks back fail: eth_estimateGas/eth_call -> `-32000 World state unavailable`; `eth_getProof` -> `4444 Pruned history unavailable` if head state is available, else `World state unavailable`; eth_getBalance and similar account queries return `null` when state missing (`Optional.empty` -> null) (verify per method).
- Chain (block body/receipt) pruning: `ChainPruningOptions` `--Xchain-pruning-enabled` strategy `ALL|BAL|NONE` default **BAL** (only block access lists pruned by default; blocks retained), retained blocks `ChainPrunerConfiguration.HISTORY_PRUNE_BLOCKS = 14299 epochs * 32 = 457,568` blocks, frequency 256 blocks, pre-merge pruning quantity 100/op, `--history-expiry-prune` (deprecated convenience flag, `DataStorageConfiguration.DEFAULT_HISTORY_EXPIRY_PRUNE_ENABLED=false`). Pruned BAL -> `4444 Pruned history unavailable` (`EthGetBlockAccessList`, `DebugGetRawBlockAccessList`); pre-Amsterdam BAL query -> `-32001 Resource not found`. What other block/receipt/log methods return for pruned blocks: not verified (likely `null`/empty).
- `--receipt-compaction-enabled` true; `--revert-reason-enabled` false (revert reason in receipts only; eth_call revert data works regardless).
- Sync: `--sync-mode` (default SNAP if `--network` given, else FULL; CHECKPOINT deprecated -> SNAP; SNAP2 exists); until synced `CHAIN_HEAD_WORLD_STATE_NOT_AVAILABLE` -32008.

## 5. Quirks / deviations from execution-apis & other clients
- `eth_call` requires 2nd param; no block overrides in eth_call; `eth_estimateGas` default tag `pending`.
- RLP decode error in `eth_sendRawTransaction` surfaces as `-32602 Invalid block param (block not found)`.
- Revert error message format `Execution reverted (reason)`, code 3, plus raw `data`.
- Nonce too low = `-32001` (not -32000); insufficient funds = `-32004`; many limit errors share `-32005`. Tx-pool errors for replacement use `-32000`.
- `eth_getLogs` rejects `toBlock > head` and `from > to` with -32602 (geth returns empty / different message); range limit applies as `to - from > 5000`; no result-size cap.
- Unknown block hash / future number returns `null` for state getters; `-39001 Unknown block` for unset safe/finalized.
- newPayload never `ACCEPTED`. Engine port serves only ENGINE+ETH namespaces by default.
- Engine versions are explicitly fork-gated per call (`-38005 Unsupported fork`), getBlobs V2 vs V3 coexist.
- `--rpc-tx-feecap=0` currently means unlimited (planned to change to "0 fee").
- Host-header allowlist defaults to localhost (rebind protection): requests with other Host get 403 unless `--host-allowlist=*`.
- Duplicate tags (`X` and `main-rel-vX`) make naive tag sorting wrong.
