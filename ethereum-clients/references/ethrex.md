# ethrex (execution)

Rust (edition 2024, toolchain 1.93.0). GitHub: https://github.com/lambdaclass/ethrex. Local: `~/Projects/ethereum/ethrex` (blobless partial clone), default branch `main`.
Latest release: `git tag --sort=-v:refname | grep -v -- '-rc' | head -1` (currently `v31.0.0`). Release tags are cut on `release/vX.Y.Z` branches and are NOT ancestors of `main`, so `git describe` on main is meaningless (see section 7). Everything below verified against main @ 1394dc305 unless marked (unverified).

## 1. Orientation

- One monorepo, one binary: `cmd/ethrex` (L1 client; L2 sequencer is built into the same binary behind the `l2` feature / `cmd/ethrex/l2`, `build_l2.rs`). Entry: `cmd/ethrex/ethrex.rs` (`main`) -> `initializers.rs` (`init_l1`, `init_tracing`) ; CLI in `cmd/ethrex/cli.rs` (clap derive `Options`, `Subcommand`: `RemoveDB`, `Import`, `ImportBench`, `Export`, ...). Every flag also has an env var `ETHREX_*`.
- Crates that matter for L1:
  - `crates/networking/rpc` (crate `ethrex-rpc`): all JSON-RPC (HTTP/WS/authrpc). Entry `rpc.rs`.
  - `crates/networking/p2p`: devp2p (discv4/discv5, rlpx, eth/snap, sync in `sync/`, `sync_manager.rs`, `tx_broadcaster.rs`).
  - `crates/blockchain`: `blockchain.rs` (`Blockchain`, import, mempool admission `validate_transaction`), `mempool.rs`, `payload.rs` (builder), `fork_choice.rs`, `tracing.rs`, `simulate.rs` (eth_simulateV1 engine), `error.rs` (`MempoolError`, `ChainError`).
  - `crates/vm/levm` (own EVM, "LEVM"), `crates/vm` (wrapper `Evm`, `backends`).
  - `crates/storage` (`store.rs` `Store`, `layering.rs` trie layer cache, `journal.rs` reorg journal, backends `backend/rocksdb.rs` and `backend/in_memory.rs`).
  - `crates/common` (types, `types/constants.rs`, `rlp`, `trie`, `crypto`, `config`).
- L2 only (ignore): `crates/l2`, `crates/prover`, `crates/guest-program`, `crates/l2/networking/rpc` (L2 RPC extension).
- Docs: `docs/l1/architecture/crate_map.md` is the crate map.

## 2. JSON-RPC server (`crates/networking/rpc/rpc.rs`)

- Framework: axum + tower-http `CorsLayer::permissive()` (all origins). Built in `bind_api` (binds, fail-fast with `RpcStartupError`) then `BoundRpc::serve`. `start_api` is the compat wrapper.
- Up to three listeners: HTTP (`handle_http_request`), WS (`ws_upgrade_handler` -> `handle_websocket`), AuthRPC (`authrpc_router` -> `handle_authrpc_request`). WS shares the HTTP listener when `ws.addr == http.addr` exactly (GET+Upgrade routed to WS). Since `--ws.addr/--ws.port` default to http values, `--ws.enabled` alone gives WS on 8545. AuthRPC never shares a listener.
- Handler pattern: trait `RpcHandler` (`parse` + `handle`; `call` records metrics) with one struct per method (e.g. `GetBalanceRequest`). `RpcApiContext` holds `storage`, `blockchain`, `syncer`, `gas_tip_estimator`, `rpc_gas_cap`, `allowed_namespaces`, `log_query_limits`, etc.
- Dispatch: `map_http_requests` -> checks `RpcNamespace` (enum in `utils.rs`; prefix `txpool` = variant `Mempool`) -> per-namespace `match` on method string:
  - `map_eth_requests`, `map_debug_requests`, `map_admin_requests`, `map_web3_requests` (also `web3_sha3`), `map_net_requests`, `map_mempool_requests` (`txpool_*`), `map_testing_requests` (`testing_buildBlockV1`, disabled by default), `map_engine_requests`.
  - To find a method's handler: grep the quoted method name in `rpc.rs`, then the struct name.
- Handler files: `eth/{account,block,transaction,logs,filter,fee_market,gas_price,gas_tip_estimator,max_priority_fee,client,simulate,call_bundle,block_access_list}.rs`; `debug/*.rs` (raw getters, execution witness, chain config, bad blocks, set_head); `tracing.rs` (debug_trace*); `engine/{payload,fork_choice,blobs,client_version,exchange_transition_config,in_flight}.rs`; `admin/{mod,peers}.rs`; `net/mod.rs`; `mempool.rs` (txpool); `types/*.rs` (RpcBlock, receipts, overrides, block identifiers).
- Namespace gating: methods outside `--http.api` return `-32601` with message `Method not found: <m> (the '<ns>' namespace is not enabled on this endpoint; add it to --http.api)` (`MethodNotServedHere`). So "Method not found" can mean disabled, not unimplemented: read the parenthetical. `engine_*` on public HTTP returns `-32601` pointing at the authrpc port; CLI rejects `--http.api engine`. The same allowlist applies to `eth_subscribe` on WS.
- AuthRPC (`map_authrpc_requests`) serves ONLY `engine_*` and `eth_*`; other namespaces -> `-32601 ... only serves the 'engine' and 'eth' namespaces`.
- Implemented eth_*: chainId, syncing, blockNumber, getBlockByNumber/Hash, getHeaderByNumber/Hash, getBalance/Code/StorageAt/**getStorageValues**/getTransactionCount/getProof, getBlockTransactionCountBy*, getUncleCountBy*, getTransactionByHash/ByBlock*AndIndex, getRawTransactionBy*, getTransactionReceipt, getBlockReceipts, **getBlockAccessList** (EIP-7928), call, estimateGas, createAccessList, **simulateV1**, **callBundle**, sendRawTransaction, getLogs, newFilter/newBlockFilter/newPendingTransactionFilter/uninstallFilter/getFilterChanges/getFilterLogs, gasPrice, maxPriorityFeePerGas, feeHistory, blobBaseFee, **config** (EIP-7910), subscribe/unsubscribe (WS only).
- debug_*: getRawHeader/Block/Transaction/Receipts/BlockAccessList, executionWitness, executionWitnessByBlockHash, chainConfig, getBadBlocks, setHead, traceTransaction/traceBlockByNumber/traceBlockByHash/traceCall.
- admin_*: nodeInfo, peers, peerScores, syncStatus, setLogLevel, addPeer. net_*: version, listening, peerCount. txpool_*: content, contentFrom, status, inspect. web3_*: clientVersion, sha3.
- **NOT implemented** (grep confirms absent): eth_accounts, eth_sign, eth_sendTransaction, eth_signTransaction (no wallet), eth_protocolVersion, eth_mining/hashrate/coinbase/getWork/submitWork, eth_getUncleByBlock*AndIndex, eth_getTransactionBySenderAndNonce, eth_sendRawTransactionSync (EIP-7966), eth_getAccount, eth_subscribe types `logs`/`syncing`; debug_storageRangeAt/accountRange/dumpBlock/getModifiedAccounts/traceBlock(raw)/standardTraceBlockToFile/etc.; admin_removePeer/datadir/etc.; net_* extras. Unknown -> `-32601 Method not found: <name>`.
- Public HTTP/WS: no auth, no rate limit, no request timeout, no explicit body limit (axum default 2 MiB for the `String` extractor, inferred, unverified). Only `/debug/pprof/allocs*` GET routes exist on HTTP (jemalloc feature).

## 3. Engine API (`crates/networking/rpc/engine/`)

- Served on authrpc only (`--authrpc.port 8551`, `127.0.0.1`). Dispatch `map_engine_requests` in `rpc.rs`; advertised list `CAPABILITIES` (26 entries) in `engine/mod.rs` (`engine_exchangeCapabilities` returns it verbatim, ignoring the CL's list).
- Versions dispatched: `forkchoiceUpdatedV1-V4`; `newPayloadV1-V5` (+ ethrex-specific `newPayloadWithWitnessV4/V5`); `getPayloadV1-V6`; `getPayloadBodiesBy{Hash,Range}V1`, `V2`; `getBlobsV1-V4`; `getClientVersionV1`; `exchangeTransitionConfigurationV1` (deprecated, still served). Fork mapping: newPayloadV3/getPayloadV3 = Cancun, V4 = Prague (getPayloadV4 also rejects Osaka; V5 = Osaka), newPayloadV5/getPayloadV6/FCUV4 = Amsterdam (BAL, custody columns param on FCUV4). Verify exact fork per version via `validate_fork`/`UnsupportedFork` checks in `engine/payload.rs`.
- Quirk: `engine_getBlobsV4` is dispatched but NOT in `CAPABILITIES` (getBlobsV1-V3 are). `getBlobsV1` rejects post-Osaka (`UnsupportedFork`); request cap 128 hashes (`GET_BLOBS_V1_REQUEST_MAX_SIZE`) -> `TooLargeRequest` -38004. getPayloadBodies cap 1024 (`GET_PAYLOAD_BODIES_REQUEST_MAX_SIZE`).
- Wrong-fork payload/attributes -> `-38005 Unsupported fork`. Other codes in `RpcErr` (`utils.rs`): -38001 unknown payload, -38002 invalid forkchoice state, -38003 invalid payload attributes, -38004 too large, -38006 too deep reorg. Invalid payloads return a normal `PayloadStatus` INVALID (`invalid_with_err`), not an RPC error. During snap sync `newPayload` returns SYNCING (`handle_new_payload_v*` in `engine/payload.rs`); during a deep-reorg pass also SYNCING.
- Quirk: in `fork_choice.rs` `parse`, unparseable `payloadAttributes` are logged (`warn`) and treated as `None` (FCU succeeds without building) instead of -38003.
- Execution of payloads runs on a dedicated `block_executor` thread (`start_block_executor` in `rpc.rs`); duplicate in-flight newPayloads wait on the running one (`engine/in_flight.rs`).
- JWT: `authentication.rs` `require_jwt` middleware; HS256, requires `iat`, `exp` not validated, |now - iat| > 60 s -> HTTP 401 (body `missing token` / `invalid token` / `stale or future token`). Secret file default `jwt.hex` in CWD, auto-generated if absent.
- Limits: body max 128 MiB (`AUTHRPC_MAX_BODY_SIZE`, HTTP 413), in-flight budget `--authrpc.max-inflight-body-size` (waits 8 s then HTTP 503), body read timeout 30 s (HTTP 408). Warning logged if no CL message for 30 s.
- `engine_getClientVersionV1` / `web3_clientVersion` string: `ethrex/v{version}-{branch}-{commit}/{os-arch}/rustc-v{rustc}` (`ClientVersion` in `rpc.rs`).

## 4. Behaviours

### Error codes/messages (`crates/networking/rpc/utils.rs`: `RpcErr` + `impl From<RpcErr> for RpcErrorMetadata`)
- Revert: code `3`, `data` = revert bytes hex, message `execution reverted: <decoded>`. `get_message_from_revert_data`: `0x` -> `Execution reverted without a reason string.`; 4-byte data -> the selector hex; otherwise assumes `Error(string)` layout (bytes 36..68 length) and, if it cannot decode (custom error with args, Panic), message becomes `execution reverted: tried to decode error from abi but failed: ...` (data still correct). Halt (OOG, invalid opcode): code 3, no data, `execution halted: reason=..., gas_used=...`.
- Bad params `-32602` (`BadParams` prefix `Invalid params: `; `InvalidParams` verbatim; `MissingParam`; `BadHexFormat` -> `invalid argument N : hex string without 0x prefix`; `WrongParam` -> `Field 'x' is incorrect or has an unknown format`). Internal `-32603`. Generic `-32000` (`ServerError`, used for all mempool rejections). `-32005` limit exceeded (log work, too many queries in flight). `-32001` resource not found (`ResourceNotFound`, data = `block not found: <id>`). `4444` pruned history (`PrunedHistoryUnavailable`). `-32015` `Vm execution error`. `-32600` invalid request. `-38026`/`-32602` etc. from eth_simulateV1 (`MethodError`).
- Mempool rejections (`MempoolError` in `crates/blockchain/error.rs`, mapped by `From<MempoolError> for RpcErr` -> `-32000`, message verbatim). Messages are ethrex's own, NOT geth's: `Nonce for account too low`, `Account does not have enough balance to cover the tx cost`, `Attempted to replace a pooled transaction with an underpriced transaction`, `Transaction gas limit exceeded`, `Transaction intrinsic gas cost above gas limit`, `Transaction chain id mismatch, expected chain id: N`, `Tip cap X wei below the configured minimum of Y wei`, `Transaction sender is a contract account (EIP-3607)`, `Mempool N% full; rejecting gapped-nonce tx ...`. Clients matching geth strings ("nonce too low", "insufficient funds", "replacement transaction underpriced", "already known") will not match. Resubmitting an already-pooled tx returns its hash with no error.
- Header/block not found: state reads (`eth_getBalance/Code/StorageAt/TransactionCount/getProof`, `eth_call`'s block) -> `-32001` `Resource not found` with data `block not found: 0x..` (`BlockIdentifierOrHash::not_found`). Block/tx/receipt getters (`eth_getBlockBy*`, `getHeaderBy*`, receipts) return `null`. `eth_blobBaseFee` etc. may return `-32000 Header not found` (`eth/block.rs`).
- Unavailable state: `resolve_state` in `eth/account.rs`: block known but state missing -> `4444 Pruned history unavailable: state for block 0x.. is unavailable` once synced; while syncing -> `-32603 ... not available yet: the node is syncing`.

### eth_call / eth_estimateGas / createAccessList (`eth/transaction.rs`)
- Params: tx, block (default `latest`), 3rd state overrides (`types/state_override.rs`, supports balance/nonce/code/state/stateDiff/movePrecompileToAddress), 4th block overrides (`types/block_override.rs`). `eth_createAccessList` accepts state overrides as an extension, no block overrides; 4th param rejected.
- Gas cap: `simulation_gas_limit`/`cap_simulation_gas`; default gas = fork's per-tx allowance for the block (`get_max_allowed_gas_limit`), capped by `--rpc.gascap` (50M). Applies also to `debug_traceCall`.
- Revert in `eth_call` -> `RpcErr::Revert` (code 3 + data); success returns output hex. After Amsterdam `eth_call` lifts the EIP-8037 execution gas cap (`ExecutionGasCap::Lifted`), `eth_estimateGas` keeps it (`Enforced`).
- `EstimateGasRequest::handle` algorithm: (1) plain value transfer shortcut: no calldata, `to` has no code, no overrides -> `0x5208`; (2) ceiling = min(request gas, block allowance, gascap), then recapped by sender balance (`recap_with_account_balances`, subtracts value and blob cost, uses `max_fee_per_gas` else `gas_price`; balance override honoured); (3) run once at ceiling (failure -> revert/halt error returned); (4) re-run at `gas_used`, if success return it (exact, no search); (5) else geth-like binary search starting from `(gas_used+refund+2300)*64/63`, stops when relative gap < `ESTIMATE_ERROR_RATIO` = 1.5%. Result may thus slightly overshoot minimum.
- Nonce defaults to the account's on-chain nonce at the block when absent.

### eth_getLogs / filters (`eth/logs.rs`, `eth/filter.rs`)
- Range limit: `to - from > --rpc.max-blocks-per-filter` (100000) -> `-32602 query exceeds max block range 100000` (reth wording). Result cap `--rpc.max-logs-per-response` (20000) -> `-32602 query exceeds max results 20000, retry with the range A-B` (single-block queries exempt). Work estimate (blocks x addresses x topic alternatives; unfiltered = 100/block) over `--rpc.max-log-query-work` -> `-32005 log query too expensive ...`; shared budget full -> `-32005 too many log queries in flight, retry later` (queries <= 10000 units exempt).
- Other errors: `to` above head -> `-32602 block range extends beyond current head block`; `from > to` -> `-32602 invalid block range params`; `blockHash` with range -> BadParams; unknown `blockHash` -> `-32000 Unknown block hash 0x..`.
- Matching uses header logs bloom first. Log objects include `blockTimestamp`. Pre-pivot (snap-synced, no bodies) ranges fail/return nothing; see section "state/history" below.
- Polling filters: `FILTER_DURATION` 5 min inactivity expiry (cleanup task in `bind_api`); `getFilterChanges` on log filters reports partial ranges instead of failing when over limits.

### Block tags (`types/block_identifier.rs`)
- `BlockTag`: earliest/finalized/safe/latest/pending. `earliest` = `Store::get_earliest_block_number` (genesis, or snap pivot / backfill frontier on snap-synced nodes). `safe`/`finalized` come from the last forkchoiceUpdated; before any FCU they are unset -> getters return `null`, state reads `-32001 block not found`.
- **`pending` = `latest`** (no pending block is ever built: `update_pending_block_number` has no caller; `TODO(#1112)`). Exceptions: `eth_getHeaderByNumber("pending")` returns `null`; `eth_getTransactionCount(addr,"pending")` = max(on-chain nonce, highest mempool nonce + 1) (`Mempool::get_nonce`, ignores gaps).
- EIP-1898 objects supported (`blockHash`/`blockNumber`; `requireCanonical` accepted, not enforced). Block param max 1024 chars. Numbers must be 0x hex (decimal -> `BadHexFormat`).

### Fees
- `eth_feeHistory` (`eth/fee_market.rs`): exactly 3 params required; `blockCount` max 1024 (`MAX_BLOCK_COUNT`, off-spec -> `-32602 Too large block_count`); percentiles <= 128, ascending in [0,100]; includes `baseFeePerBlobGas`/`blobGasUsedRatio`; newest block clamps to head; range clamps to earliest block; reward only computed if percentiles given. Rewards for legacy/2930 txs treated as 0 (see `calculate_percentiles_for_block`).
- `eth_gasPrice` (`eth/gas_price.rs`) = latest base fee + tip estimate. `eth_maxPriorityFeePerGas` = tip estimate. `GasTipEstimator` (`eth/gas_tip_estimator.rs`): last 21 blocks (head-20..head), 3 lowest effective tips per block, median; cached per head hash; empty blocks -> last tip, initial `MIN_GAS_TIP` = 1_000_000 wei; floored by `--mempool.min-tip` (1 wei).

### eth_sendRawTransaction + mempool
- `SendRawTransactionRequest` (`types/transaction.rs`, handle in `eth/transaction.rs`): hex must be `0x`; decode via canonical RLP; L2 types rejected (`Invalid transaction type`). Blob txs (type 3) must be the network wrapper with sidecar -> `add_local_blob_transaction_to_pool`; others `add_local_transaction_to_pool`. Validation: `Blockchain::validate_transaction` (`crates/blockchain/blockchain.rs`), against the LATEST header/state (not pending): size, init-code size, EIP-7825 gas cap (Osaka 16,777,216; Amsterdam `TX_MAX_TOTAL_GAS_LIMIT_AMSTERDAM`), gas <= block gas limit, tip <= fee cap, min tip, type-4 checks, intrinsic gas, blob fee >= min, nonce >= on-chain, EIP-3607 (7702 delegations allowed), balance, cumulative pending cost vs balance, chain id, gap admission.
- Limits (`crates/common/types/constants.rs`): `MAX_TX_SIZE` 131072 B, `MAX_BLOB_TX_SIZE` 1 MiB (tx + sidecar). Pool: `--mempool.maxsize` 10000 regular txs (FIFO eviction, `Mempool::add_transaction`), blob sub-pool `MAX_BLOB_MEMPOOL_SIZE` 512 evicted by value/nonce (`crates/blockchain/mempool.rs`).
- Replacement (`Mempool::find_tx_to_replace`): same sender+nonce; must strictly raise BOTH fee cap and tip, then each by >= `--mempool.price-bump` (10%); blob txs: 100% on fee cap, tip and blob fee (`--mempool.blob-price-bump`); blob <-> non-blob replacement rejected (`ReplacementTypeMismatch`); other type changes allowed.
- Nonce gaps: allowed (no hard queue), per-account queued cap 64 (`MaxQueuedTxsPerAccountExceeded`), and rejected when pool occupancy >= 90% (`GapAdmissionDeniedUnderPressure`).
- Type 4 (7702): rejected pre-Prague (`Eip7702TxPreFork`), empty auth list rejected. Frame txs (EIP-8141) pre-Hegota rejected. Type-3 pre-Cancun etc. covered by blob checks (unverified details).
- `--mempool.private` stops RPC-submitted txs being gossiped. No local-tx journal/persistence (in-memory only; unverified).
- `txpool_*` (`mempool.rs`): everything is reported under `pending`; `queued` is always empty/0 (no pending/queued split). `txpool_status` hex strings.

### Batching, WS
- Batches: HTTP, WS and authrpc all accept arrays (`RpcRequestWrapper`). Limits: empty batch -> `-32600 Invalid Request: empty batch is not a valid Request`; > `MAX_BATCH_SIZE` 1000 -> `-32600 batch too large`; also total `eth_getProof` storage keys across a batch <= `MAX_PROOF_STORAGE_KEYS` 1024 (`-32005`). Requests execute sequentially in order, no response-size cap. Unparseable HTTP body -> HTTP 200 with `-32000 Invalid request body` and id `""`.
- WS (`subscription_manager.rs`, `handle_eth_subscribe`): only `newHeads` and `newPendingTransactions` (optional 2nd param full tx object); other type -> `-32602 Unsupported subscription type`. Caps: 128 per connection (`MAX_SUBSCRIPTIONS_PER_CONNECTION`), 10_000 total, 512-msg per-subscriber channel. `eth_subscribe` over HTTP is not supported. WS parse errors -> `-32700 Parse error` / `-32600 Invalid Request`.

### eth_simulateV1 (`eth/simulate.rs`, engine in `crates/blockchain/simulate.rs`)
- Supports blockStateCalls, block/state overrides, `traceTransfers`, `validation`, `returnFullTransactions`; `deny_unknown_fields`. Limits: 256 blocks (`MAX_SIMULATE_BLOCKS`), 5000 calls/block, 10000 total (`-38026 client limit exceeded: ...`), 5 s wall-clock timeout (`SIMULATE_TIMEOUT`, -> `-32603 eth_simulateV1 timeout`). Also `eth_callBundle` (`eth/call_bundle.rs`).

### debug_trace* (`tracing.rs`, `crates/blockchain/tracing.rs`)
- Tracers: `callTracer` (DEFAULT when no `tracer` given, unlike geth's struct logger), `prestateTracer` (`diffMode` and `includeEmpty` mutually exclusive), `opcodeTracer` (EIP-3155/structLogger shape; config `disableStack`, `enableMemory`, `disableStorage`, `enableReturnData`, `limit`). No JS tracers, no 4byteTracer/muxTracer/flatCallTracer; unknown name -> `-32602` serde error.
- Defaults: `timeout` 5 s (`DEFAULT_TIMEOUT`, error `Tracing Timeout` -> `-32603`), `reexec` 128 (`DEFAULT_REEXEC`): if the parent state is not stored, ancestors are re-executed up to `reexec` blocks, else `Exceeded max amount of blocks to re-execute for tracing`. `callTracer` for a tx returns a single frame object (geth-compatible). `debug_traceCall` accepts `txIndex`, state and block overrides.
- Errors from tracing are `-32603 Internal Error: <msg>` (not typed).

### State / history storage and pruning
- Store: RocksDB (`crates/storage/backend/rocksdb.rs`), trie layer cache (`layering.rs`) flushed to disk `DB_COMMIT_THRESHOLD` = 128 blocks behind head (`store.rs`); older states are NOT kept (not an archive node, no archive mode flag). So state queries on blocks older than ~128 behind head -> `4444 Pruned history unavailable` (when synced); tracing can re-execute up to `reexec` blocks.
- Reorg journal (`journal.rs`) only for reorgs, pruned at finality; `--max-reorg-depth` override.
- Snap sync (default) stores only headers below the pivot: bodies/receipts/txs for pre-pivot blocks are absent, so `eth_getBlockBy*`/`getTransactionByHash`/receipts return `null` and `eth_getLogs` over such ranges fails (`docs/l1/fundamentals/history_backfill.md`). `--history.chain postmerge|all|N` backfills bodies+receipts (not state); `earliest` tag reports the pivot/backfill frontier (stale genesis on upgraded nodes unless backfill enabled). `--history.transactions N` limits tx-index window.
- Pre-merge chains are unsupported (`docs/known_issues.md`: no pre-London base fee path); Byzantium-era receipts below Byzantium cannot be represented.
- Execution witnesses: `MAX_WITNESSES` 128 kept (`--precompute-witnesses`), `debug_executionWitness*`.

## 5. Quirks and deviations (summary)
- Mempool error strings differ from geth (see above); duplicate submission is silent success.
- `pending` aliases `latest` everywhere except `getHeaderByNumber` (null) and `getTransactionCount`.
- `engine_getBlobsV4` not advertised; `exchangeCapabilities` ignores input.
- `callTracer` is the default tracer; only 3 tracers exist.
- `txpool_*` has no queued bucket; txpool methods off unless `--http.api txpool`; default `--http.api` is only `eth,net,web3`, so `debug_*`, `admin_*`, `txpool_*` return `-32601` by default.
- `eth_feeHistory` requires all 3 params and caps `blockCount` at 1024; max priority fee based on only 21 blocks.
- Revert message decode assumes `Error(string)`; custom errors give an `abi decode failed` message (data field is correct).
- Log objects carry `blockTimestamp` (execution-apis#639), which makes hive rpc-compat byte-exact eth_getLogs/receipt cases fail against the pinned corpus (`docs/known_issues.md`; excluded in `.github/scripts/check-hive-results.sh`). Invalid storage key -> `-32602` (newer spec) while old hive fixtures expect `-32000`.
- Non-standard extras: `eth_getBlockAccessList`, `debug_getRawBlockAccessList` (EIP-7928, Amsterdam; pre-Amsterdam block -> `-32001`), `eth_callBundle`, `eth_getStorageValues`, `debug_executionWitness`, `testing_buildBlockV1`, `admin_setLogLevel`, `admin_peerScores`, EIP-8025 proof error codes -39001..-39004.
- `eth_getBlockByNumber` etc. on unknown block returns `null`; state reads on unknown block return `-32001` (follows newer execution-apis, differs from geth `-32000 header not found`).
- Public RPC listens on loopback by default; CORS fully permissive.

## 7. Docs and versions
- In-repo docs (mdbook `book.toml`, `docs/SUMMARY.md`): `docs/CLI.md` (all flags), `docs/l1/running/{configuration,startup,consensus_client,monitoring}.md`, `docs/l1/architecture/{overview,crate_map,block_execution,mempool,sync_state_machine}.md`, `docs/l1/fundamentals/{databases,history_backfill,snap_sync,sync_modes,networking}.md`, `docs/known_issues.md`, `docs/developers/release-process.md`, `docs/crate_reviews/ethrex_rpc_review.md`, `crates/networking/rpc/README.md` (short), `CHANGELOG.md` (perf/observability only, not a release changelog).
- Versions: tags `vX.Y.Z` (final) and `vX.Y.Z-rc.N` (candidates) are the real release tags for the single `ethrex` binary (L1 and L2 share them; `l2_v0.0.1-rc1`, `backup/*`, `bal-devnet-*` are stray). Releases are cut from `release/vX.Y.Z` branches (`remotes/origin/release/v31.0.0`) which are not merged back as ancestors, so `git describe` on main gives the old ancestor `v26.0.0-rc.1-174-g...`, and `[workspace.package].version` on main lags (30.0.1 while v31.0.0 exists). Right way: `git tag --sort=-v:refname | grep -v -- '-rc' | head -1` (or `--sort=-creatordate`); to check what a tag contains use `git show <tag>:path` or `git log <tag>`. v31.0.0 dated 2026-11-01, v30.0.1 2026-10-22. Check whether a feature is in a release with `git merge-base --is-ancestor <commit> <tag>`. Blobless clone: `git show <tag>:file` may trigger a network fetch.
