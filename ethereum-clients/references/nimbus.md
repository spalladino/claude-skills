# Nimbus (consensus)

Language: Nim (chronos async, presto REST router, nim-web3 for Engine API). GitHub: https://github.com/status-im/nimbus-eth2. Local: `~/Projects/ethereum/nimbus` (blobless partial clone; checked out on `stable`; `origin/unstable` is the dev branch, `origin/testing` also exists; `stable` = latest release, so recent unreleased API work is only on `unstable`).
Latest release tag: `git tag --sort=-creatordate | head` (non-semver CalVer `vYY.M.patch`; tag `nightly` also exists and is not a release). At time of writing: `v26.10.2` (2026-10-23); version also in `beacon_chain/version.nim` (versionMajor/Minor/Build). Submodules under `vendor/` are NOT initialised locally: nim-presto (REST server/router, content negotiation), nim-web3 (Engine API JSON-RPC types/methods), nim-json-rpc, nim-chronos, nim-libp2p are absent. Consensus spec fork names in code: up to Fulu (Fusaka) shipped, plus Gloas (ePBS) and Heze in progress (Glamsterdam).

## 1. Orientation

- Binaries (`beacon_chain/`): `nimbus_beacon_node.nim` (BN, big `main`/`installRestHandlers`/`onSlot*`), `nimbus_validator_client.nim` (VC, logic in `validator_client/`), `nimbus_signing_node.nim` (remote signer), `nimbus_light_client.nim`. `ncli/` has dev tools (resttest, era, ncli_db).
- Layout: `rpc/` (all REST handlers, despite the name there is no JSON-RPC any more; removed v22.6), `spec/` (datatypes per fork, `spec/eth2_apis/` REST types + (de)serialization + REST client calls, `spec/mev/` builder API types), `el/` (Engine API client), `validators/` (block production `block_payloads.nim`, `beacon_validators.nim`, keystore mgmt, slashing protection, validator_pool), `validator_client/` (VC services), `consensus_object_pools/` (`blockchain_dag.nim`, `consensus_manager.nim`, `column_quarantine.nim`), `gossip_processing/` (`block_processor.nim`), `fork_choice/`, `sync/`, `networking/`.
- CLI options: `beacon_chain/conf.nim`, type `BeaconNodeConf` (BN, `confutils` objects with `name:`/`defaultValue:`), VC config `ValidatorClientConf` further down the same file (~line 1000+); EL options (`--el`, `--jwt-secret`) in the same file + `el/el_conf.nim`. Shared REST server construction: `nimbus_rest_common.nim` (`RestServerRef.init`). Ports/constants: `spec/network.nim`. Docs of flags: `docs/the_nimbus_book/src/options.md` (checked by `scripts/check_docs_help_msg.sh`).
- Defaults: REST port 5052 (`defaultEth2RestPort`, "not part of the spec, Lighthouse's port"), p2p TCP/UDP 9000, QUIC 9001, metrics 8008, VC keymanager port 5062 (`defaultVcKeymanagerPort`), Engine API default `http://127.0.0.1:8551`.

## 3. Behaviour

**Enabling / network config (conf.nim, BeaconNodeConf):** REST is DISABLED by default (`--rest`, default false). `--rest-address` default 127.0.0.1, `--rest-port` 5052, `--rest-allow-origin` (Option; sets CORS origin on `RestRouter.init(..., allowedOrigin)`; no flag = no CORS headers), `--rest-statecache-size` 3, `--rest-statecache-ttl` 60 (s), `--rest-request-timeout` 0 = infinite (this is the HTTP headers/request-receive timeout, `httpHeadersTimeout`, not a handler timeout), `--rest-max-body-size` 16384 (KB), `--rest-max-headers-size` 128 (KB; tied to `ClientMaximumValidatorIds` in rest_types.nim). No rate limiting anywhere in the REST server. No auth on the beacon API (only Keymanager has bearer token). Server flags: `QueryCommaSeparatedArray, NotifyDisconnect` (comma-separated array query params like `id=1,2`). Server ident string `nimbusAgentStr`.

**Error format:** `RestApiResponse.jsonError(status, msg[, stacktrace])` in `eth2_rest_serialization.nim` -> `{"code": <int>, "message": "<msg>"}` (+ `"stacktraces": [..]` when a detail string is given, usually the underlying `$error`), `Content-Type: application/json`. Lists of per-item failures: `jsonErrorList` -> `{"code","message","failures":[{"index","message"}]}`. Keymanager errors use `keymanagerApiError` (same shape). Typical statuses: 400 bad id/param (`InvalidStateIdValueError`, `InvalidBlockIdValueError`, "Incorrect state identifier value"), 404 not found (`StateNotFoundError` "Could not get requested state", `BlockNotFoundError` "Block header/data has not been found"), 406 `ContentNotAcceptableError` (Accept not json/ssz), 410 removed, 500 for unimplemented / `InvalidAcceptError` (negotiated type that has no branch), 503 `BeaconNodeInSyncError` ("Beacon node is currently syncing and not serving request on that endpoint").

**state_id** (`StateIdent`, decode in `eth2_rest_serialization.nim` `decodeString`; resolve in `rpc/rest_utils.nim` `getBlockSlotId`): `head`, `genesis`, `finalized`, `justified`, decimal slot, or `0x` 32-byte root. NOTE: `getBlockSlotId`:
- Slot: rejected if `slot.epoch > head.epoch + 1` ("Requesting state too far ahead of current head", 404 not 400), else `dag.getBlockIdAtSlot` ("History for given slot not available" if before the DAG tail/pruned). Empty slots resolve to a state advanced via replay.
- Root: matches `headState.root`, else searched only in head state's `state_roots` (last `SLOTS_PER_HISTORICAL_ROOT` = 8192 slots); otherwise "State root not found - use by-slot lookup to query deep state history". Only state roots in that window work.
- `justified`: max(head state's current_justified_checkpoint.epoch, finalized epoch) state at that epoch start. `genesis`: "Genesis state not available / pruned" if gone.
- All state-not-resolvable cases are 404 `StateNotFoundError` with the detail in `stacktraces`.
**block_id** (`BlockIdent`, `getBlockId`): `head`, `genesis`, `finalized`, slot, or root. There is NO `justified` for blocks (400 "Incorrect block identifier value"). Slot ids resolve only to a proposed block at exactly that slot (skipped slot -> 404).

**State availability / history:** `withStateForBlockSlotId` (rest_utils.nim): uses head state if it matches, else `node.stateTtlCache` (`rpc/state_ttl_cache.nim`: LRU of recently-used advanced states, `slotDifferenceForCacheHit = 5*SLOTS_PER_EPOCH`) else replays from the closest stored state via `dag.updateState`. States are stored only every `EPOCHS_PER_STATE_SNAPSHOT = 32` epochs (`blockchain_dag.nim`) and replayed from there, so deep queries are slow but work. Handler bodies are barred from `await` (macro `disallowInterruptions`). `--history=prune|archive|column-archive` (conf.nim `HistoryMode`, default `prune`): prune removes blocks/states older than `dag.horizon` (`block_pools_types.nim`: `min(finalizedHead.slot, head.slot - MIN_EPOCHS_FOR_BLOCK_REQUESTS*SLOTS_PER_EPOCH)`, ~5 months mainnet); pruning done incrementally in `blockchain_dag.nim` `pruneHistory` called from `nimbus_beacon_node.nim` slot-end. `archive` keeps back to checkpoint-sync state or genesis; `--reindex` rebuilds the state index (needs era files, docs: `era-store.md`, `history.md`). Checkpoint-synced nodes lack pre-checkpoint history until backfilled.

**Content negotiation:** Accept via presto `preferredContentType(jsonMediaType, sszMediaType)` (`rpc/rest_utils.nim` defines `application/json`, `application/octet-stream`, `text/event-stream`); JSON is the first/default. Unsupported Accept -> 406. Responses with `Eth-Consensus-Version` header (lowercase `eth-consensus-version`): `ethHeaders` in `eth2_rest_serialization.nim`; when `--rest-allow-origin` is set also adds `access-control-expose-headers`. Block production adds `Eth-Execution-Payload-Blinded|Value`, `Eth-Consensus-Block-Value` (v3) or `Eth-Execution-Payload-Included`, `Eth-Builder-Url` (v4). Request bodies: `decodeBodyJsonOrSsz` / `decodeBody(..., version)` choose by `Content-Type`; publishing blocks needs `Eth-Consensus-Version` request header (else 400). SSZ state/block endpoints serve the stored raw SSZ for blocks (`dag.getBlockSSZ`), encode on the fly for states.

**execution_optimistic / finalized:** `rest_utils.nim` `getBlockOptimistic`, `getStateOptimistic`, `getBidOptimistic`, `getShufflingOptimistic`: `Opt.none` (serialised via the Opt writer; exact JSON form, null vs omitted, unverified) before Bellatrix, else `dag.is_optimistic(bid)`; `finalized` = `dag.isFinalized(bid)`. Writers: `jsonResponseFinalized`, `jsonResponseWOpt`, `jsonResponseWRoot` (duties: `dependent_root`). SSZ responses carry no flags.

**503 cases:** only where the node must be synced: validator duties/production/attestation_data/aggregate/sync-contribution/liveness endpoints via `getSyncedHead` (`rest_utils.nim`: `node.isSynced(head)` = head within `syncHorizon` (hidden `--sync-horizon`, default = slots in 10 min) of wall slot; also "Requesting far ahead of the current head" if slot > head.slot + 2 epochs) and, for block production (`/eth/v3/validator/blocks`, v4), also `not head.executionValid` (optimistic head => 503). `POST /eth/v2/beacon/blocks` returns 503 if routing errors. Beacon-namespace reads (states, headers, blocks) are served while syncing/optimistic. `/eth/v1/node/health` NEVER returns 503: `200` synced, `206` if `syncOverseer.syncInProgress()` (TODO in code to add 503).
`/eth/v1/node/syncing`: `head_slot`, `sync_distance`, `is_syncing`, `is_optimistic` (post-Bellatrix, from `head.executionValid`), `el_offline` (post-Capella, `not elManager.hasAnyWorkingConnection`).

**Blocks/publishing:** `POST /eth/v2/beacon/blocks`: only `broadcast_validation=gossip` supported (`consensus`/`consensus_and_equivocation` -> 500 "Only `gossip` broadcast_validation option supported"); returns 202 `BlockValidationError` if routed but not accepted into the DAG(`res.get().isNone`); Fulu: needs `blobs`/`kzg_proofs` (blobs.len*CELLS_PER_EXT_BLOB), builds data column sidecars with `assemble_data_column_sidecars`. Gloas: forwards signed block to winning builder if `Eth-Builder-Url` header present.
`/eth/v1/beacon/headers`: `parent_root` query returns 500 `NoImplementationError`; only `slot` or head.

**Blobs / data columns (Fulu):** no blob sidecars REST: `/eth/v1/beacon/blob_sidecars/{id}` -> 410. `/eth/v1/beacon/blobs/{block_id}` (`versioned_hashes` filter) reconstructs blobs from stored data column sidecars with `recover_blobs_from_data_columns` (needs >=50% columns stored, i.e. supernode / `--peerdas-supernode` or full custody; otherwise result is empty/incomplete, check `recover_blobs_*` in `spec/peerdas_helpers.nim` - unverified exact empty behaviour). `/eth/v1/debug/beacon/data_column_sidecars/{block_id}` (`indices`) returns only stored columns via `handleDataSidecarRequest` (missing/pruned columns are silently skipped, 200 with partial/empty list; 404 only for unknown block). Unknown/pruned block -> 404.
Retention: `nimbus_beacon_node.nim` `pruneDataColumns`: deletes columns older than `(MIN_EPOCHS_FOR_BLOB_SIDECARS_REQUESTS + 1) * SLOTS_PER_EPOCH` slots (4096 epochs ~18 days mainnet) every slot unless `--history=column-archive`. Docs (`history.md`) say `--history=archive` archives blobs but the code only skips pruning for `column-archive` (docs likely stale). Sync side: `sync/sync_overseer2.nim` `getSidecarsHorizon` / `shouldGetColumns` use `MIN_EPOCHS_FOR_DATA_COLUMN_SIDECARS_REQUESTS` (4096). Custody: `--peerdas-supernode` (all columns), `--light-supernode` (first half). Quarantine: `consensus_object_pools/column_quarantine.nim`.

**SSE `/eth/v1/events`:** topics validated by `validateEventTopics` (unique, non-empty, else 400 "Invalid topics value"; LC topics 400 if LC serving off). Accept must be `text/event-stream`. Implemented topics: `head`, `head_v2`, `block`, `block_gossip`, `single_attestation`, `voluntary_exit`, `bls_to_execution_change`, `proposer_slashing`, `attester_slashing`, `data_column_sidecar`, `finalized_checkpoint`, `chain_reorg`, `contribution_and_proof`, `light_client_finality_update`, `light_client_optimistic_update`, `execution_payload`, `execution_payload_gossip`, `execution_payload_available`, `execution_payload_bid`, `payload_attestation_message`, `fast_confirmation`, `payload_attributes`, `proposer_preferences`. No `attestation` and no `blob_sidecar` (removed). Headers `Cache-Control: no-cache, no-store`, `X-Accel-Buffering: no`; no periodic keep-alive/heartbeat. Stream ends when any handler future finishes (client disconnect).

**Node API:** `/eth/v1/node/peers` etc. include non-spec `agent` and `proto` fields. `peer_id` parse error 400, unknown 404.

## 4. Engine API client (`beacon_chain/el/`)

- `el_manager.nim` `ELManager` holds `elConnections: seq[ELConnection]` (multiple ELs supported by repeating `--el=<url>`; JWT per URL via `#jwt-secret=<hex>` / `#jwt-secret-file=<path>` URL fragment, or global `--jwt-secret=<file>`; TOML form in `el_conf.nim` `EngineApiUrlConfigValue`). No `--el` => "Running without execution client - validator features disabled"; newPayload returns none, fcU returns syncing, getPayload none. Legacy `--web3-url` hidden/superseded.
- JWT: `getJsonRpcRequestHeaders` sends `Authorization: Bearer <HS256 token with iat=now>` per request (`spec/engine_authentication.nim`, `getSignedIatToken`, `loadJwtSecretFile`). If no `--el` given the default URL `http://127.0.0.1:8551` is used with the well-known hard-coded `defaultJwtSecret` (`d4e567...8fa3`, execution-apis PR 302) ONLY when no `--jwt-secret` file is passed (`getDefaultEngineApiUrl`). Secret in URL fragment and `jwtSecretFile` are mutually exclusive.
- Methods and versions (dispatch by fork in `newPayload*` ~line 910): newPayloadV1 (Bellatrix), V2 (Capella), V3 (Deneb), V4 (Electra/Fulu, +execution_requests), V5 (Gloas, ExecutionPayloadV4); forkchoiceUpdated with PayloadAttributesV1..V4 (V4 used for Gloas, includes slot_number/gas limit); getPayload response types GetPayloadV4/V5/V6 (Electra/Fulu/Gloas); `engine_getBlobsV2` (Fulu) and `engine_getBlobsV4` (Gloas, custody-cell bitarray) in `getBlobsV2*`/`getBlobsV4*`, driven by `el_getblobs_service.nim` (`attemptGetBlobs*`; gets blobs from EL when block or a column sidecar arrives to build columns without waiting for gossip; counters `engine_getBlobs ...`). Exact RPC method wrappers (`engine_newPayloadV*`) live in vendor/nim-web3 (absent).
- Timeouts (constants): `spec/datatypes/bellatrix.nim` `NEWPAYLOAD_TIMEOUT = 8s`, `FORKCHOICEUPDATED_TIMEOUT = 8s`; `el_manager.nim`: `GETPAYLOAD_TIMEOUT = 1s` (+500 ms processing overhead deadline), `GETBLOBS_TIMEOUT = 1s`, `engineApiConnectionTimeout = 5s`, `web3RequestsTimeout = 8s` (eth_*), `multiTimeout = 1s` (extra wait for other ELs after the first response), reconnect loop sleeps 10 s (`connectedRpcClient`). Block-import deadline can instead be "~1 s before next slot" (`block_processor.nim` `nextSlotDeadline`, `startExecutionValidity` for Fulu early validation).
- Retries: `retryUntilCancelled` template: retries same request with exponential backoff 10 ms -> 160 ms until the deadline cancels it; disabled if connection state is `Degraded` or `retry=false` (retry set to `not dag.is_optimistic(head)` in block_processor).
- Connection health: `ELConnectionState` NeverTested/Working/Degraded with hysteresis (`connectionStateChangeHysteresisThreshold = 15` consecutive-ish failures to degrade; success decays counter by 80%); degraded closes the web3 connection and reconnects. `checkChainId` loop verifies EL chain id/network matches (`eth1Network`). Metrics: `engine_api_responses`, `engine_api_request_duration_seconds`, `engine_api_timeouts`, `engine_api_last_minute_forkchoice_updates_sent`.
- Multi-EL consensus: for newPayload and fcU requests are sent to all ELs; first response wins, others get `multiTimeout`; `compareStatuses` + `ELConsensusViolationDetector`: if ELs disagree (valid vs invalid) logs "Execution layer consensus violation detected" and returns `invalid`. getPayload asks all ELs and picks highest `blockValue`; getBlobs takes first successful response (`firstOrCancel`).
- Status handling: `consensus_object_pools/consensus_manager.nim` `PayloadExecutionStatus.to(OptimisticStatus)`: `valid`->valid; `syncing`/`accepted`->notValidated (optimistic import); `invalid`/`invalid_block_hash`->invalidated. `block_processor.nim` `getExecutionValidity`/`addBlock`: invalidated newPayload -> `VerifierError.Invalid`, block rejected; no response/timeout (`Opt.none`) -> falls back to `verifyPayload` => `notValidated` (optimistic). Optimistic sync is always on (since v22.12; `--optimistic` obsolete); head with `executionValid` false => VC duties/block production 503. fcU invalid on previously-valid head -> warns "check execution client for faults and restart", `mark_root_invalid` in fork choice (`consensus_manager.nim` `forkchoiceUpdated`, `updateHeadWithExecution` loops until valid head). Gloas: payload validated when envelope arrives (`OptimisticStatus.missing` for block-only).
- fcU for proposal: `consensus_manager.nim` sends a warm-up fcU with payload attributes before the slot; `getPayload` reuses it by payload-id (`lastPayloadReq`) else sends "last-minute" fcU then sleeps 500 ms before getPayload. Checks extraData size and withdrawals match; mismatch => error and EL payload dropped.

## 5. Validator client, Keymanager, builder/MEV

- VC: `nimbus_validator_client.nim` + `validator_client/` (`api.nim` request fan-out with scoring, `fallback_service.nim`, `duties_service.nim`, `block_service.nim`, `attestation_service.nim`, `sync_committee_service.nim`, `payload_attestation_service.nim`, `doppelganger_service.nim`). Options: `--beacon-node` (list, default `http://127.0.0.1:5052`), `--beacon-node-mode=bestscore|fallback` (default bestscore: ask all nodes, pick best), `--block-monitor-type=event|poll` (default event), `--distributed` (DVT), `--builder-boost-factor`. Embedded VC runs inside BN (keys loaded in BN, `validators/`).
- Keymanager API (`rpc/rest_key_management_api.nim`): enabled with `--keymanager` (default false) AND required `--keymanager-token-file` (BN exits otherwise; empty token fatal). Options: `--keymanager-port` (BN default 5052 = shares the REST server if address/port equal to REST, else separate server; VC default 5062), `--keymanager-address` (127.0.0.1), `--keymanager-allow-origin`. Auth `checkAuthorization`: `Authorization: Bearer <token>`; missing/malformed header -> 401, wrong token -> 403, body `{"code","message":"Invalid Authorization Header"}`. Router query validator `validateKeymanagerApiQueries`. Includes non-standard `/eth/v1/remotekeys/distributed`.
- Builder (MEV-boost) flow, `validators/block_payloads.nim`: enabled by `--payload-builder` (default false) + `--payload-builder-url` (repeatable; changelog v26.10.2 calls it `--builder-url`, conf.nim names it `payload-builder-url`; unverified whether alias). Options: `--builder-boost-factor` (default 100, uint64), `--local-block-value-boost` (default 10, uint8 percent; legacy Prysm-style, applies when no per-request boost given), `--builder-min-bid` (Gwei, 0), `--builder-max-execution-payment` (Gwei, max uint64), `--suggested-gas-limit` (default 60_000_000 `defaultGasLimit`). Validator registrations come via `POST /eth/v1/validator/register_validator` into `node.externalBuilderRegistrations` (syntactic validation only) or `validators/keystore_management.nim` builder config + Keymanager `builder_config`.
- Proposal: `collectBids` fetches builder bid (`getBuilderBid`; timeout `BUILDER_PROPOSAL_DELAY_TOLERANCE = 1500 ms` in `spec/mev/fulu_mev.nim`; verifies builder BLS signature) in parallel with the local EL payload (`getExecutionPayload`, 1 s). `useBuilderPayload`: builder bid used iff present and (no local payload or `builderBetterBid(boostFactor, builderValue, engineValue)`). `builderBetterBid` semantics: factor 0 => never builder, 100 => `>=`, uint64 max => always builder, otherwise `builderValue*factor/100 >= engineValue` (overflow => builder); legacy `localBlockValueBoost` variant compares scaled values with `(boost+100)%`. Builder ignored (local payload used) when the liveness failsafe fires (`spec/validator.nim` `livenessFailsafeInEffect`: >3 contiguous or >5 of recent missed slots) unless `isExcludedTestnet`, when builder errors/times out ("Payload builder error" notice), or when head block's execution hash can't be loaded. If neither: error "Engine payload is not available" (production fails; no fallback beyond EL). REST per-request: `builder_boost_factor` query on `/eth/v3/validator/blocks/{slot}` (default 100; invalid => 400 with no message); response headers `Eth-Execution-Payload-Blinded`. Blinded block submission: `validators/message_router_mev.nim` (`submitBlindedBlock`); for Gloas bids come via ePBS gossip/builder REST (`getExecutionPayloadBidFromBuilder`, `selectBestBid`, `collectBids`). v3 block production returns 500 for Gloas+ ("produceBlockV3 won't work past Fulu"); use v4 (`POST /eth/v4/validator/blocks/{slot}`, registered in rest_validator_api.nim, `produceBlockV4Response`).
- Validator-API specifics: `getSyncedHead` gating (see 3); `prepare_beacon_proposer` stores dynamic fee recipients (`spec/eth2_apis/dynamic_fee_recipients.nim`, `consensusManager.getFeeRecipient`); duties `dependent_root`.

## 6. Quirks / deviations (verified in code unless noted)

- REST off by default; binds 127.0.0.1 only. Beacon API port 5052 (Lighthouse's).
- States resolved by root only within last 8192 slots; `justified` supported for states, not for blocks. Too-far-ahead slot state requests give 404 (not 400).
- `/eth/v1/node/health` returns 206 while syncing, never 503. `/eth/v1/beacon/headers?parent_root=` -> 500 not implemented.
- `broadcast_validation` only `gossip`; others 500 (spec says 400/validation behaviour).
- `getBlobs` is column-reconstruction based; partial custody => incomplete/empty. `blob_sidecars` is 410 (removed in Fulu per beacon-APIs #577). Debug column endpoint silently omits missing columns.
- `execution_optimistic` omitted pre-Bellatrix (`Opt.none`).
- Many removed endpoints answer 410 not 404.
- Non-spec extras: `agent`/`proto` in node peers, `/nimbus/*`, keymanager `remotekeys/distributed`, `eth-builder-url` handling, `debug/fork_choice` `extra_data` incl. `confirmed_root`/fast confirmation (Nimbus ahead of spec on unstable-spec features).
- Default JWT secret is a hard-coded constant when using the default EL URL without `--jwt-secret`.
- `--history=archive` does not retain data columns (only `column-archive` does) despite book text.
- v3 block production unsupported from Gloas; only v4.
- Heze/Gloas code paths contain `debugHezeComment`/`debugGloasComment` stubs, so ePBS API behaviour on `stable` may be incomplete (see unstable).

## 7. Tests

- Unit tests: `tests/` flat `test_*.nim`, aggregated by `tests/all_tests.nim`; run via Makefile `make test` / `make DISABLE_TEST_FIXTURES_SCRIPT=1 test`. Relevant: `test_eth2_rest_serialization.nim` (JSON/SSZ round-trips), `test_keymanager_api.nim` (suites per endpoint: ListKeys, ImportKeystores, Fee recipient, Gas limit, Graffiti, Builder config, remote keys; spins up a real REST server), `test_el_manager.nim`, `test_el_conf.nim`, `test_engine_api_conversions.nim`, `test_engine_authentication.nim`, `test_block_payloads.nim` (builder bid selection / boost), `test_mev_calls.nim`, `test_honest_validator.nim`, `test_validator_client.nim`, `test_light_client*.nim`, `test_block_processor.nim`, `test_blockchain_dag.nim`, `test_response_utils.nim`, `test_conf.nim`. Beacon REST handlers have no direct unit tests.
- REST conformance: `ncli/resttest.nim` + rule vectors `ncli/resttest-rules.json` (~880 entries: `topics`, `request{url,headers}`, `response{status operator, headers, body jstructcmps}`; covers valid and invalid ids such as `finalised`, `0x`, 2^64 overflow, for states/blocks/headers/blobs/validator/node/config/debug endpoints). Run end-to-end by `tests/simulation/restapi.sh` (starts local BN, then `build/resttest`). To find the test for a behaviour: grep the URL path in `ncli/resttest-rules.json`; for keymanager grep the endpoint in `tests/test_keymanager_api.nim`. Spec tests: `tests/consensus_spec/`. Kurtosis e2e: `run-kurtosis-check.sh`, `kurtosis-network-params.yml`; local testnet: `scripts/launch_local_testnet.sh`.
- Test status listings: `AllTests-mainnet.md`, `ConsensusSpecPreset-*.md` (auto-generated).
