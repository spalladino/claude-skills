## 3. Behaviour

### Errors and status codes
- Body always `{"code": <u16>, "message": "<err + ': ' + sources>", "failures": [{"index","message"}]?}` (`EthErrorResponse` in `http_api/src/error.rs`; `failures` only for indexed batch errors). `code` is a number, not a string. 204 has no body.
- Mapping (`Error::status_code`): 404 = `BlockNotFound`, `StateNotFound`, `ValidatorNotFound`, `PeerNotFound`, `AttestationNotFound`, `TargetStateNotFound`, `ExecutionPayloadEnvelopeNotFound`; 204 = `BlockNotSeen`; 400 = all `Invalid*` (block/state/slot id, query, JSON, SSZ, phase header), pre-fork errors (`BlockPreFulu`, `StatePreElectra`, `StatePreCapella`, `StatePreFulu`, `StatePreGloas/PostGloas`), `EpochRewardsNotFinal`, `EpochBeforePrevious`, `EventTopicsEmpty`, `InvalidBlobIndex`, `VersionedHashNotInBlock`, `UnableToPublishBlock`; 500 = `Internal` (any bare `anyhow` error via `?`), `UnableToProduceBeaconBlock`, `LivenessTrackingNotEnabled`, `ExecutionPayloadNotAvailable`; 501 = `EndpointNotImplemented`; 503 = `NodeIsSyncing`, `HeadIsOptimistic`, `HeadFarBehind`, `BlockNotValidatedForAggregation`; 403 = disabled runtime feature (plain status, no JSON body); 408 = request timeout (plain, from `helpers.rs`).
- 503 "syncing": `middleware::is_synced` (`http_api/src/middleware.rs`) applied as a layer to `eth_v1_validator_routes` and `eth_v2_validator_routes` only. `SyncedStatus` (atomic bool in `misc.rs`) is fed by `SyncToApi::SyncStatus` in `task.rs::handle_sync_statuses`; initial value `controller.is_forward_synced()` = `head_slot + max_empty_slots >= current_slot` (`fork_choice_store/src/store.rs`). NOT sync-checked: `duties/proposer` v1, `prepare_beacon_proposer`, v3/v4 block production, `execution_payload_envelopes`. All `/eth/v1/beacon/*`, `/debug`, `/config`, `/node` endpoints are served while syncing.
- `GET /node/health`: 200 synced / 206 syncing, never 503 and no `syncing_status` query param. `GET /node/syncing` returns `head_slot, sync_distance, is_syncing, is_optimistic, el_offline` (`node_syncing_status`; `el_offline` = all EL endpoints marked offline).
- Other 503s: block production (`validator_block`, `_v3`, `_v4`) via `ensure_extends_valid_payload` waits for the parent payload to be VALID, else `HeadIsOptimistic`; `validator_attestation_data` returns `HeadFarBehind` if `head_slot + max_empty_slots < slot` (`--max-empty-slots`, default 32 via `ValidatorConfig::default`) and waits up to 1 s (`BLOCK_EVENT_WAIT_TIMEOUT`) for the current-slot block / polls payload status every 50 ms, `HeadIsOptimistic` if head is invalid or still optimistic on timeout; aggregate_attestation -> `BlockNotValidatedForAggregation`.

### state_id / block_id resolution
- Parse: `head|genesis|finalized|justified|<slot>|0x<root>` for state; same minus `justified` for block (`http_api_utils/src/{state_id,block_id}.rs`). Bad id -> 400 `Error::InvalidStateId/InvalidBlockId`.
- `state_id::state`: head -> `controller.head_state()`; genesis -> `anchor_checkpoint_provider.checkpoint().genesis()` (only `Some` if the node started from genesis; on a checkpoint-synced node `genesis` state/block -> 404); finalized/justified -> `last_finalized_state` / `justified_state`; slot -> `ApiController::state_at_slot_cached_blocking` (`fork_choice_control/src/queries.rs`); root -> `state_by_state_root` (in-memory store, else `Storage::stored_state_by_state_root`; comment says in-memory lookup is a linear search and canonical-only).
- Slot -> state: in-memory chain if within unfinalized store (replays empty slots via `state_cache.state_at_slot`); finalized slots use `state_at_slot_cache`; older uses `Storage::stored_state` (`fork_choice_control/src/storage.rs`): loads nearest persisted state at/below slot and replays stored blocks + `process_slots`. So historical states exist at ANY slot as long as an earlier persisted state + blocks are on disk, but replay is slow. A slot more than `MIN_SEED_LOOKAHEAD` epochs past the current epoch fails with `Error::EpochTooFarInTheFuture`, which surfaces as 500 (bare anyhow -> `Internal`), not 400.
- `block_id::block`: head/finalized from controller; genesis same genesis-origin caveat; slot -> `block_by_slot` (store, then `Storage::finalized_block_by_slot`); root -> `block_by_root` (store, finalized db, unfinalized db). Empty slot with slot id -> 404 `block not found`. Finalized blocks are stored BLINDED by default; `block_by_root/slot` call `unblind_block` which asks the EL via `engine_getPayloadBodiesByHash` -> if the EL no longer has it, error `BlockError::PayloadBodyNotFound` -> 500 (`From<BlockError> for Error`). `block_headers`/`block_id_headers`/`block_root` use `stored_block*` (no EL needed). See `store_execution_payloads` in `Storage::new` (unverified which flag enables storing payloads).
- Storage modes (`types/src/nonstandard.rs::StorageMode`, flags in `grandine_args.rs`): `--prune-storage` (only checkpoint block+state), default `Standard{custom_data_availability_window}`, `--archive-storage` (never prunes; `Mutator::prune_old_records` in `fork_choice_control/src/mutator.rs` returns early). Persisted state cadence `--archival-epoch-interval` (default 32 epochs, `DEFAULT_ARCHIVAL_EPOCH_INTERVAL`). Standard pruning horizon for blocks/states = `Config::min_epochs_for_block_requests(phase)` (33024 epochs on mainnet pre-Gloas, 14299 at Gloas; `Store::min_checked_block_availability_epoch`). `--back-sync` (deprecated alias `--back_sync`) downloads history before the checkpoint: with `--archive-storage` to genesis and reconstructs states, without it only to the block-request window; conflicts with `--prune-storage`. `--state-slot`, `--force-checkpoint-sync`, `--force-reset-beacon-db` also exist.

### Content negotiation, headers, flags
- Request SSZ body: `Content-Type: application/octet-stream` accepted on block/blinded block publish, v2 pool attestations, aggregate_and_proofs, payload attestations/bids/envelopes, proposer_preferences, v4 block (`EthJsonOrSsz*` in `extractors.rs`, `deserialize_json_or_ssz` in `standard.rs`). Everything else JSON only. v2 publish/aggregate endpoints REQUIRE `Eth-Consensus-Version` (400 "eth-consensus-version header expected"); v1 block publish accepts JSON without it; SSZ always needs it. Missing JSON Content-Type -> 400 (`ContentTypeHeaderInvalid`); workaround feature `PatchHttpContentType` (for Prysm) inserts `application/json`.
- Response: `EthResponse::json_or_ssz` (`http_api_utils/src/response.rs`) returns SSZ iff `Accept` lists `application/octet-stream` anywhere (q-values are parsed/sorted in `accept_content_type_list` but the loop returns SSZ on any octet-stream match, so `octet-stream;q=0.1,application/json;q=1` still gets SSZ; `*/*` or no Accept -> JSON). No 406 is ever returned. SSZ-capable endpoints are the list in `book/src/beacon_node_api.md` (blocks, blinded blocks, blob_sidecars, blobs, pending_*, proposer_lookahead, validator_balances/identities POST, debug states, data_column_sidecars, attestation_data, aggregate_attestation v2, block production v2/v3).
- Response headers (only where the data is fork-specific): `Eth-Consensus-Version` (also JSON `version`), block production adds `Eth-Consensus-Block-Value`, `Eth-Execution-Payload-Blinded`, `Eth-Execution-Payload-Value`, `Eth-Execution-Payload-Included`, `Eth-Builder-Url`. JSON-only body fields: `execution_optimistic`, `finalized`, `dependent_root`, `meta`.
- `execution_optimistic` comes from `WithStatus.status.is_optimistic()`; `finalized` from `store.is_slot_finalized`. Stored-on-disk (finalized) data is always reported `valid` + `finalized:true`; `genesis` is `valid_and_finalized`. Debug data_column_sidecars by unknown block root returns `execution_optimistic:true, finalized:false`.

### Events (SSE)
- `beacon_events` in `standard.rs`; channels in `fork_choice_control/src/events.rs` (`EventChannels`); `--max-events` default 100 (`DEFAULT_MAX_EVENTS`, per-topic broadcast buffer; slow client's stream is terminated, no replay). Topics: head, block, block_gossip, chain_reorg, finalized_checkpoint, attestation, single_attestation, voluntary_exit, proposer_slashing, attester_slashing, bls_to_execution_change, contribution_and_proof, blob_sidecar, data_column_sidecar, payload_attributes, plus Gloas: head_v2, execution_payload, execution_payload_gossip, execution_payload_available, execution_payload_bid, payload_attestation_message, proposer_preferences. No `topics` -> 400; unknown topic -> 400 query error. `KeepAlive::default()`.
- Pre-Gloas, `head`/`block`/`chain_reorg` events are withheld while the head/block is optimistic and sent once the EL validates it (`Mutator::handle_potential_head_change`, `send_head_events_if_head_node_became_valid`, comment "Vouch treats all head events as non-optimistic"), so events can arrive late during EL sync. `payload_attributes` only fires for proposers registered via `prepare_beacon_proposer` unless feature `AlwaysPrepareExecutionPayload`.

### Blobs and data columns
- Retention: Standard mode keeps blobs/columns for `min_epochs_for_blob_sidecars_requests` / `min_epochs_for_data_column_sidecars_requests` (both 4096 epochs ~18 days on mainnet, `types/src/config.rs`), overridable with `--data-availability-window` (conflicts with archive/prune; `StorageMode::min_epochs_for_*`). Pruned by `Mutator::prune_old_records` -> `Storage::prune_old_blob_sidecars` / `prune_old_data_column_sidecars` (chooses by phase at the pruning slot). Archive keeps everything it received. Prune mode: kept in memory only. Custody: default minimal (`CUSTODY_REQUIREMENT` 4 groups + validator custody), `--semi-supernode` (64), `--supernode` (128); `book/src/peerdas.md`.
- `GET /eth/v1/beacon/blob_sidecars/{id}` and `/blobs/{id}`: block resolved first (404 if unknown). Pre-Fulu: `controller.blob_sidecars_by_ids` silently skips missing -> pruned blobs give `200 {"data": []}`, not 404. Post-Fulu (`is_peerdas_activated`): `construct_blobs_from_data_column_sidecars` reads stored columns by root; if fewer than half of `NumberOfColumns` (128) are stored it returns `[]` (200); if >=50% but not the first 64 it runs `eip_7594::recover_matrix` on the dedicated executor (cost: CPU, metrics `columns_reconstruction_time`) and rebuilds. So a minimal-custody node (4+ groups) cannot serve blobs post-Fulu (returns empty 200) unless semi-supernode/supernode. Block with no commitments -> `[]`. `?indices=` validated against `max_blobs_per_block(epoch)` (400 `InvalidBlobIndex`); `/blobs?versioned_hashes=` 400 `VersionedHashNotInBlock` if not in block.
- `GET /eth/v1/debug/beacon/data_column_sidecars/{id}?indices=`: 400 `BlockPreFulu` pre-Fulu; 400 `InvalidColumnIndex` if >= 128; returns only columns that are stored (can be a partial list); with a raw block root that is unknown to fork choice it still returns any stored columns (debug aid).
- Gossip/EL fetch side: `eth1_api/src/execution_blob_fetcher.rs` calls `engine_getBlobsV1/V2` after `newPayload` to fill missing sidecars (only if `is_forward_synced`).

### Rate limits, timeouts, CORS
- No rate limiting, no auth, no TLS on :5052; `DefaultBodyLimit::disable()` (unbounded request body; `routing.rs`).
- Timeout `--timeout` ms, default `DEFAULT_TIMEOUT` = 1000 s (`runtime/src/defaults.rs`; book says 1000000 ms). Implemented as a `tower` timeout layer -> `408 Request Timeout` (`http_api_utils/src/helpers.rs`). Docs claim SSE streams are not cut off (timeout only applies to producing the response).
- CORS: `CorsLayer` with `allow_origin` = `--http-allowed-origins` (comma list; `*` = any) else only `http://<http-address>:<port>` (`HttpApiConfig::with_address`). `headers_to_allow_origin` in `grandine_args.rs`.

## 4. Engine API client (CL -> EL)

- Code: `eth1_api/src/eth1_api/http_api.rs` (`Eth1Api`: HTTP via `web3` crate; `execute`, `request_with_fallback`), `eth1_api/src/eth1_api/embed_api.rs` (embedded-EL variant, feature `embed`: Grandine as a Nethermind plugin, direct calls, no HTTP/JWT), `eth1_api/src/execution_service.rs` (message loop), `eth1_api/src/eth1_execution_engine.rs` (impl of `execution_engine::ExecutionEngine`), `eth1_api/src/tasks.rs` (capability / client-version exchange), `eth1_api/src/auth.rs` (JWT), `eth1_api/src/endpoints.rs` (multi-endpoint state), `eth1_api/src/execution_blob_fetcher.rs`.
- Methods and versions (version picked from payload phase, `new_payload`/`forkchoice_updated`/`get_payload` in `http_api.rs`; constants in `eth1_api/src/eth1_api/mod.rs`): `engine_newPayloadV1..V5` (V3 Deneb, V4 Electra/Fulu with execution_requests, V5 Gloas), `engine_forkchoiceUpdatedV1..V4`, `engine_getPayloadV1..V6`, `engine_getBlobsV1/V2`, `engine_getPayloadBodiesByHashV1/V2` (V2 if EL advertises it) and ByRange V1/V2 in capabilities, `engine_exchangeCapabilities`, `engine_getClientVersionV1`; plus eth_ calls (`eth_blockNumber`, `eth_getBlockByHash/Number`, `eth_getLogs` for deposits). The `CAPABILITIES` list is advertised at every epoch start (`Mutator` tick -> `exchange_capabilities`).
- Timeouts (consts at top of `http_api.rs`, `tasks.rs`): newPayload 8 s, forkchoiceUpdated 8 s, getPayload 1 s, getBlobs 2 s, getPayloadBodies 10 s, exchangeCapabilities 1 s, getClientVersion 1 s.
- Retries: none per call. `--eth1-rpc-urls` takes multiple URLs (space-separated `num_args=1..`, comma delimiter NOT allowed); first is primary, rest `is_fallback`. `request_with_fallback` tries endpoints in order, sorted online-first; on error marks that endpoint offline (`on_error_response`) and tries the next; if all fail -> `Error::EndpointsExhausted` (`NoEndpointsProvided` if none configured). An endpoint is set online again only after a later successful call. Endpoint filtering by advertised capability (e.g. getBlobs only to endpoints that list it).
- JWT: `--jwt-secret <file>` (hex, >=32 bytes, `JWT_SECRET_SIZE_MIN_BYTES`), `--jwt-id`, `--jwt-version`. `Auth::headers` mints a fresh HS256 token (`iat` + 60 s expiry via jwt_simple `Claims`, custom claims `id`, `clv`) per request. No secret -> unauthenticated requests. No default secret path. Startup errors if `--eth1-rpc-urls` missing for non-predefined networks without `embed` (`grandine_args.rs` ~line 533).
- Flow: block import does NOT block on the EL. `transition_functions/src/*/block_processing.rs` calls `execution_engine.notify_new_payload(..., None)` (fire-and-forget); the block enters fork choice as optimistic and `Mutator::handle_notified_new_payload` later sets status:
  - VALID: payload status Valid for block + ancestors (warns if `latest_valid_hash != block hash`). INVALID: `invalidate_payload_and_descendant_payloads`. SYNCING/ACCEPTED: `else { return; }` -> stays optimistic, only a warn log in `execution_service.rs`. Call error: warn `engine_newPayload call failed`, block stays optimistic (no retry besides next tick, below).
  - `forkchoiceUpdated`: `handle_notified_forkchoice_update_result`: INVALID is treated like newPayload INVALID for the head; `latest_valid_hash` validates ancestors. SYNCING only warns.
  - Re-poll: at the end of each slot interval, if the head is still optimistic, `Mutator` re-sends `notify_new_payload` for the head (`mutator.rs` ~line 535).
- Optimistic status flows into API `execution_optimistic`, into `/node/syncing.is_optimistic`, and blocks validator duties that need a validated head (503 `HeadIsOptimistic`).
- Merge-transition checks use `allow_optimistic_merge_block_validation` = true for the real engine (`validations.rs`).

## 5. Validator, keymanager, builder

- Integrated VC: `validator/src/validator.rs` + `local_beacon_node.rs` (in-process, no HTTP); remote VC: `remote_beacon_node(s).rs`, `beacon_nodes.rs` (multi-BN with fallback, `--beacon-node-urls`). Own duty tracking: `own_*` files. Keys: `--keystore-dir/--keystore-password-file`, `validators.yml` (`keymanager/src/validator_definitions.rs`), web3signer (`signer/`). Slashing protection `slashing_protection/` (sqlite `validator/slashing_protection.sqlite`), doppelganger `doppelganger_protection/` (needs `--track-liveness` on the BN for `POST /validator/liveness`; otherwise 500 `LivenessTrackingNotEnabled`).
- Keymanager API: `validator/src/api.rs` (`run_validator_api`, `eth_v1_keymanager_routes`), separate server, default `127.0.0.1:5055`, enabled only with `--enable-validator-api`, timeout default 10 s (`VALIDATOR_API_DEFAULT_TIMEOUT`, `--validator-api-timeout`). Bearer-token auth (`authorize_token`); token file default `<data>/<network>/validator/api-token.txt` (auto-generated 256-bit hex if absent, `--validator-api-token-file` to supply). Routes: `/eth/v1/keystores` (GET/POST/DELETE), `/eth/v1/remotekeys` (GET/POST/DELETE), `/eth/v1/validator/{pubkey}/{feerecipient,gas_limit,graffiti,builder_config}` (GET/POST/DELETE), `POST /eth/v1/validator/{pubkey}/voluntary_exit`, plus the two `/eth/v2/debug/tracing/*` routes. Keystores loaded via `--keystore-dir` are `readonly` (cannot be deleted via API). Persisted changes go to `validators.yml` (`ValidatorDefinitionsWithStorage`). `grandine vc` with no keys can start and be populated via API.
- Builder / MEV-boost:
  - Flags: `--builder-url` (`--builder-api-url` deprecated), `--builder-format` (default `ssz`; `json` alt, `BuilderApiFormat`), `--builder-disable-checks`, `--builder-header-timeout` (default 1000 ms = `BUILDER_PROPOSAL_DELAY_TOLERANCE*1000`, pre-Gloas only), `--builder-max-skipped-slots` (3), `--builder-max-skipped-slots-per-epoch` (8), `--default-builder-boost-factor` (100), `--default-builder-min-bid`, `--default-builder-max-execution-payment` (+ `--allow-trusted-payments`), `--payload-builder-urls` (Gloas bids). Hard-coded: `BUILDER_BID_REQUEST_TIMEOUT` 500 ms in `builder_api/src/consts.rs`.
  - Client: `builder_api/src/api.rs` (`register_validators` -> `POST /eth/v1/builder/validators`; `get_execution_payload_header` -> `GET /eth/v1/builder/header/{slot}/{parent_hash}/{pubkey}`; `post_blinded_block` v1, `post_blinded_block_post_fulu` v2; bid signature and phase verified; payload root must equal header root else `RootMismatch`).
  - Selection: `block_producer/src/block_producer.rs` (`build_blinded_beacon_block`): builds BOTH a local block (from `engine_getPayload`) and a blinded block from the builder bid concurrently; if local MEV >= builder MEV / 100 * boost_factor -> uses local ("using more profitable local payload" log), otherwise the blinded block. Boost factor per request: `builder_boost_factor` query on `GET /eth/v3/validator/blocks/{slot}`, else per-validator `proposer_configs().builder_boost_factor(pubkey)` (`keymanager/src/proposer_configs.rs`), else the default. If no bid / builder fails / checks fail -> local block (blinded result is `None`).
  - Circuit breaker (pre-Gloas): `BuilderApi::can_use_builder_api` -> skip builder if missed slots since head > `builder_max_skipped_slots` or > `builder_max_skipped_slots_per_epoch` in last rolling epoch (bypass with `--builder-disable-checks`). Gloas version: `fork_choice_store/src/builder_circuit_breaker.rs` (withheld payloads; self-build for `TRIP_PERIOD`=1 epoch).
  - Publishing a blinded block: `publish_blinded_block(_v2)` in `standard.rs` (sends blinded block to builder to unblind, then gossips; `Eth-Builder-Url` header can pin the builder).
  - Registrations: `POST /eth/v1/validator/register_validator` -> `ApiToValidator::ValidatorRegistrations`; errors are `IndexedError` list (deviation, see handler doc comment). `GET /validator/registered` lists them (kept for ~3 epochs per book).
- Block production API options: `validator_block` (v2) always local; `validator_block_v3` blinded-or-full with the logic above; both honour `skip_randao_verification` (then `randao_reveal` must be empty -> 400 `InvalidRandaoReveal`) and `graffiti`. v3 returns 400 `StatePostGloas` once Gloas is active (use v4 POST).

## 6. Quirks / deviations

- `POST /eth/v1/beacon/blocks` (v1) returns 202 for a block that failed validation (logs warn, no 400) and for an ignored (already seen) block; v2 with `broadcast_validation=gossip` (default) also returns 202 for failures; only `consensus` / `consensus_and_equivocation` return 400 (`InvalidBlock`) (`publish_signed_block` vs `publish_signed_block_v2`).
- Block publish v1 for Fulu is "temporary" (comment: `SignedAPIBlock` can't be disambiguated Electra/Fulu without the version header).
- `canonical` in `/beacon/headers*` is always `true` (TODO in `block_id_headers`); `GET /beacon/headers` with no params returns the block at the head slot and never more than one header.
- Future-slot state requests give 500, not 400/404 (see section 3). Missing history -> 404 `state not found` / `block not found`.
- `validator_register_validator` returns failures as `failures[]` list; `ValidatorNotInCommittee` error deliberately disabled (Vouch sends no `validator_index`, comment in `error.rs`).
- Selection endpoints (`beacon_committee_selections`, `sync_committee_selections`) -> 501, so distributed validators (Obol/SSV middleware) that need them cannot use Grandine as BN.
- `book/src/beacon_node_api.md` says `POST /eth/v1/beacon/rewards/attestations/{epoch}` is not implemented, but the route and `attestation_rewards` handler exist on `develop` (503 `NodeIsSyncing` if head is behind the epoch end; 400 `EpochRewardsNotFinal` until rewarding epoch is past). Docs lag code; trust `routing.rs`.
- `Accept` parsing: any `application/octet-stream` entry wins SSZ regardless of q-values (JSON preference is ignored); `Accept: */*` -> JSON.
- `payload_attributes` events are sparse by default (see above). `head`/`block` events delayed while optimistic.
- Genesis state/block endpoints only work on nodes that started from genesis; after checkpoint sync they 404 even though `/beacon/genesis` still answers (reads anchor state's genesis_time/root).
- Default HTTP timeout is 1000 s (effectively none); unbounded request body size; no auth.
- Finalized blocks served unblinded by asking the EL; EL missing the payload body -> 500.
- Grandine does not support light client serving; `slasher` crate exists but its options are `#[clap(skip)]` with a TODO "not working properly".
- Runtime flags (`--features A,B` or `PATCH /features`; list in `features/src/lib.rs`) change API behaviour: `ServeCostlyEndpoints`, `ServeLeakyEndpoints`, `LogHttpBodies/Headers/Requests`, `PatchHttpContentType`, `AlwaysPrepareExecutionPayload`, `Trust*` (skip validation of own objects), `Dump*`.
