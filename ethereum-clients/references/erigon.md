Go (module `github.com/erigontech/erigon`, go 1.26). GitHub: https://github.com/erigontech/erigon. Local: `~/Projects/ethereum/erigon` (blobless partial clone), default branch `main`.
Latest release: real tags are `vMAJOR.MINOR.PATCH` (3.x line: v3.7.1, v3.8.0, v3.8.1 at time of writing); find with `git tag | grep -E '^v3\.[0-9]+\.[0-9]+$' | sort -V | tail`. Release branches: `origin/release/3.8` etc. `git describe` on main is useless (`v3.0.0-beta1-6301-g...`).

## 3. Engine API

- Handler: `execution/engineapi/engine_server.go` (`EngineServer`, `HandleNewPayload`, forkchoice, `getPayload`, `getBlobs`), method wrappers + advertised capability list in `execution/engineapi/engine_api_methods.go`, interface `execution/engineapi/interface.go` (`EngineAPI`), types `execution/engineapi/engine_types/`, errors `execution/engineapi/engine_helpers/`. Registered as namespace `engine` via `engineAPI()`; served only on authrpc listener (`createEngineListener` in `cmd/rpcdaemon/cli/config.go`), HTTP + WS (WS gets the jwt secret too).
- Versions implemented (from `interface.go`): newPayloadV1..V5; forkchoiceUpdatedV1..V4 (V4 takes `custodyColumns`, Amsterdam/Gloas-era); getPayloadV1..V6; getPayloadBodiesByHashV1/V2, getPayloadBodiesByRangeV1/V2; getClientVersionV1; getBlobsV1..V4 (V4 takes `cellIndices` bitarray, must be 16 bytes else InvalidParams); getInclusionListV1; `engine_exchangeCapabilities`. NOT present: exchangeTransitionConfigurationV1.
- Error codes (`execution/engineapi/engine_helpers/`): -38001 Unknown payload, -38002 Invalid forkchoice state, -38003 Invalid payload attributes, -38004 Too large request, -38006 Too deep reorg; -38005 Unsupported fork is `rpc.UnsupportedForkError` in `rpc/errors.go`. Limits: getPayloadBodiesByHash / ByRange count > 1024 => -38004 (V2 verified; check V1 path too); getBlobs > 128 hashes => -38004. Version/fork mismatch checks run only AFTER the SYNCING short-circuit (unknown head => SYNCING, not -38003/-38005); see comments in `engine_server.go`.
- newPayload behaviour: missing parent => starts `engine_block_downloader` and returns SYNCING, but first waits up to one slot (`SecondsPerSlot`) for the download to finish so it can fully validate; busy/too-far-away execution => SYNCING; forkchoiceUpdated never returns ACCEPTED. getBlobs returns `null` (not a partial list) if the txpool returns fewer bundles than hashes (V1 path logs "returning nil blobs list"); needs the txpool enabled (`txpool.ErrPoolDisabled` otherwise).
- JWT: `cmd/rpcdaemon/cli/config.go` `ObtainJWTSecret`: path `--authrpc.jwtsecret`, default `<datadir>/jwt.hex` (embedded; standalone rpcdaemon falls back to `./jwt.hex`); file is auto-generated (0600, 32 random bytes hex) if missing; wrong length => error. Validation `rpc/http.go` `CheckJwtSecret`: HS256 only, `Authorization: Bearer`, requires `iat`, window `jwtTokenExpiry = 60s` (both stale and future), exp optional; failures are HTTP 403 with text bodies ("missing token", "stale token", ...), not JSON-RPC errors.
- Ports/flags: `--authrpc.addr` (localhost) `--authrpc.port` 8551, `--authrpc.vhosts` (default localhost), `--authrpc.timeouts.{read,write,idle}` (same defaults as http: 30s / 30m / 120s). Engine listener has compression forced off, no CORS, no subscription ingress limits change (`SetSubscriptionLimit` applies).
- Extra: SSZ-REST Engine transport under `/engine/...` on the same authrpc port, JWT-gated (`execution/engineapi/sszrest_handler.go`, `sszrest_wire.go`; `AuthenticatedEngineRESTHandler` hook in config.go). Non-standard vs other clients.
- Tests: `execution/engineapi/*_test.go`, harness `execution/engineapi/engineapitester/` (`MockCl`, `EngineApiTester`).

## 4. Behaviour that commonly matters

### Error codes/messages
- Codes in `rpc/errors.go`: -32700 parse, -32600 invalid request, -32601 method not found ("the method X does not exist/is not available"), -32602 invalid params, -32603 internal, -32000 default (any untyped error), -32001 resource not found, -32005 server overloaded ("server overloaded, retry later"; also HTTP 503 when DB read slots exhausted: `kv.ErrReadTxLimitExceeded` remapped in `rpc/handler.go` `remapDBOverload`), -32015 VM error, -38010 nonce too low, -38011 nonce too high, -38012 base fee too low, -38013 intrinsic gas, -38014 insufficient funds, -38015 block gas limit, -38020/-38021 invalid block number/timestamp (simulate), -38024 sender not EOA, -38025 max initcode, -38026 client limit exceeded, -39001 `UnknownBlockCode` (`rpc/rpchelper/rpc_block.go`: `block "finalized" not available (head block: N)`), code 3 = execution reverted, 4 = `TxSyncTimeoutError`, 4444 = pruned proof (eth_getProof only).
- Execution reverted: `rpc/ethapi/api.go` `NewRevertError`: code 3, message `execution reverted` or `execution reverted: <decoded reason>`, `error.data` = hex revert bytes. Used by eth_call, eth_estimateGas (`rpc/jsonrpc/eth_call.go`), createAccessList. In simulate/callMany, VM errors are inside call results (`rpc.NewJsonError(ErrCodeVMError,...)` code -32015 in `eth_simulation.go`).
- Plain eth_call/estimateGas state-transition errors (nonce too low, `insufficient funds for gas * price + value`, `intrinsic gas too low`; strings in `execution/protocol/error.go`) are returned as untyped errors => code -32000. Only `eth_simulateV1` maps them to the -380xx codes (`txValidationError` in `eth_simulation.go`).
- Not found: `eth_getBlockByNumber/Hash` return `null` for unknown blocks (not an error); state methods on unknown block => `rpc.BlockNotFoundErr` "block not found: <id>" (code -32000); eth_call with missing header => "header not found"; eth_estimateGas => "could not find the header <sel> in cache or db"; non-canonical hash => `hash 0x.. is not currently canonical` (-32603); block above execution progress => `block N is not executed (last executed: M)` (`rpc/rpchelper/helper.go` `CheckBlockExecuted`).
- Pruned data: `state.ErrPruned` = `old data not available due to pruning` (`execution/state/history_reader_v3.go`), wrapped as `...: requested block N, history is available from block M` / `blocks are available from block` / `receipts are available from block` (gates in `rpc/jsonrpc/eth_api.go`: `checkPruneState*`, `checkPruneBlocks*`, `checkLogsAvailable`, `checkReceiptSourceAvailable`; `rpc/rpchelper/helper.go`). Plain error => -32000. eth_getProof pruned => code 4444 `Pruned history unavailable: ...`.

### eth_call / eth_estimateGas (`rpc/jsonrpc/eth_call.go`, `rpc/transactions/call.go`)
- Gas cap `--rpc.gascap` default 50,000,000 (`rpccfg.DefaultGasCap`, `ethconfig.Defaults.RPCGasCap`). eth_call: missing/zero `gas` => set to the cap (NOT block gas limit). EVM timeout `--rpc.evmtimeout` default 5m (`DefaultEvmCallTimeout`), error `execution aborted (timeout = 5m0s)`. Return data cap `--rpc.returndata.limit` default 100,000 bytes, error `call returned result on length N exceeding --rpc.returndata.limit M`. `NoBaseFee: true` (zero-fee calls allowed).
- Block param default `latest`. `pending` in eth_call/getProof => error `pending state is not supported`; in eth_estimateGas pending silently becomes `latestExecuted`.
- estimateGas algorithm: hi = args.gas if >= MinTxGas else header gas limit; capped to EIP-7825 `MaxTxnGasLimit` when Osaka (not Amsterdam); recapped to sender balance/feeCap; recapped to gascap. Plain transfer to codeless account: single run at `hi`, returns actual gas used. Else run at hi (fail => revert error / `gas required exceeds allowance (hi)`), then optimistic try at `(MaxGasUsed + CallStipend)*64/63`, then binary search with `estimateGasErrorRatio = 0.015` (stops when range < 1.5%, so estimates can be up to ~1.5% high; bisect midpoint capped at `lo*2`). Both gasPrice and 1559 fields => error `both gasPrice and (maxFeePerGas or maxPriorityFeePerGas) specified`. Insufficient balance for transfer => `insufficient funds for transfer`.
- Overrides: `rpc/ethapi/state_overrides.go` (`state` full replace vs `stateDiff`, `movePrecompileToAddress`), `rpc/ethapi/block_overrides.go`. Single-call block overrides reject `beaconRoot`, `withdrawals`, `blockHash` with error `block override "X" is not supported for this RPC method`; supported: number, difficulty, time, gasLimit, feeRecipient, prevRandao, baseFeePerGas, blobBaseFee. eth_simulateV1 supports more.
- Erigon extras: `eth_callMany` (`eth_callMany.go`, bundles + `StateContext`), `eth_fillTransaction`, `eth_getStorageValues`, `eth_sendRawTransactionSync` (default timeout 25s `--rpc.txsync.defaulttimeout`, max 1m `--rpc.txsync.maxtimeout`, error code 4 with data = tx hash).

### eth_getLogs (`rpc/jsonrpc/eth_receipts.go` `GetLogs`, `getLogsV3`, `resolveLogsRange`)
- `--rpc.blockrange.limit` default 1,000 (`end-begin > limit` => InvalidParams `query block range exceeds server limit, narrow your filter: 1000`; 0 = unlimited). `--rpc.logs.maxresults` default 20,000 => `query returns too many logs, narrow your filter: 20000` (-32602). `--rpc.logs.querylimit` default 1,000 = max addresses / alternatives per topic position => `query exceeds the maximum of %d addresses or topics per search position`. Same limits apply to eth_getFilterLogs, erigon_getLogs/getLatestLogs.
- Other errors (-32602 unless noted): `can't specify fromBlock/toBlock with blockHash`; `invalid block range params` (to < from); `block range extends beyond current head block` (from or to > latest EXECUTED block, tags resolved against latest executed; note: strict, geth would return empty); `requested block range [a, b] is beyond latest executed block N (node is still syncing)` (-32000); `node is still initializing`; unknown blockHash => `block not found: <hash>` (non-canonical hash also "not found"); pruned range => ErrPruned messages above. Default from/to when omitted = latest executed (single block).
- Receipts/log source: persisted receipt cache (`--prune.include-receipts`, default ON for fresh datadirs, `--prune.receipts.distance`) else re-execution from state history; log index (address/topic) retired with history window.
- eth_getBlockReceipts("pending") => `pending receipts are not available`.

### Block tags (`rpc/types.go`, `rpc/rpchelper/helper.go` `_GetBlockNumber`, `rpc/rpchelper/rpc_block.go`)
- Accepted: earliest(0), latest, pending, safe, finalized, plus Erigon-only `latestExecuted`; also decimal numbers as JSON strings/numbers, hex. `null` => latest.
- latest = forkchoice head set by last engine_forkchoiceUpdated (`rawdb.ReadForkchoiceHead`), falling back to Execution stage progress. State reads at "latest" use the latest-state reader only when blockNumber == execution progress. safe/finalized = forkchoice safe/finalized hashes from engine FCU; if CL never sent them: error code -39001 `block "finalized" not available (head block: N)`.
- pending: block-number resolution maps to execution progress (same as latest-executed) for state; `eth_getBlockByNumber("pending")` returns the builder's pending block only if one was broadcast to filters (`api.pendingBlock()` / `ethBackend.PendingBlock`), else `null`; `eth_getTransactionCount(.., "pending")` asks the txpool (`txPool.Nonce`, +1 if found); eth_call/getProof reject pending; estimateGas treats as latest executed; fee_history pending uses pending block if available else latest.

### Fee oracle
- `eth_gasPrice` = tip suggestion + head baseFee (`rpc/jsonrpc/eth_system.go` `GasPrice`); `eth_maxPriorityFeePerGas` = oracle tip (`rpc/gasprice/gasprice.go`). Oracle config `node/ethconfig/config.go` `FullNodeGPO`: 20 sample blocks, percentile 60, 3 txs sampled per block (`sampleNumber`), ignore-price 2 wei (`DefaultIgnorePrice`), max price 500 gwei (`DefaultMaxPrice`), default 1 mwei (GWei/1000), MaxHeaderHistory/MaxBlockHistory 0. Caches per head hash.
- `eth_feeHistory` (`rpc/gasprice/feehistory.go`): blockCount capped silently to 1024 (`maxFeeHistory`, warning only, no error); >100 reward percentiles => error `invalid percentile ...: over the query limit 100`; percentiles must be 0..100 ascending. Returns `baseFeePerBlobGas`/`blobGasUsedRatio` when applicable.

### eth_sendRawTransaction (`rpc/jsonrpc/send_transaction.go`)
- Order: `txpool.ValidateSerializedTxn` (size: 128KB for normal txs, 1MB for blob txs) -> decode (blob txs accepted wrapped) -> `checkTxFee` against `--rpc.txfeecap` default 1 ether (`tx fee (X ether) exceeds the configured cap (1.00 ether)`, 0 disables; uses feeCap*gasLimit) -> non-EIP-155 rejected unless `--rpc.allow-unprotected-txs` (`only replay-protected (EIP-155) transactions allowed over RPC`) -> chain-id check `invalid chain id, expected: X got: Y` -> post-Osaka legacy (v0) blob sidecars auto-converted to v1 cell proofs -> `txPool.Add` gRPC.
- Rejections from the pool come back as `<ImportResult>: <DiscardReason string>` (`txnprovider/txpool/txpool_grpc_server.go` `mapDiscardReasonToProto`), code -32000, e.g. `INTERNAL_ERROR: nonce too low`, `INTERNAL_ERROR: insufficient funds`, `INTERNAL_ERROR: could not replace existing tx`, `FEE_TOO_LOW: underpriced`, `FEE_TOO_LOW: replacement transaction underpriced` (blob replacement only), `ALREADY_EXISTS: already known`, `INVALID: initcode too large`, `INTERNAL_ERROR: IntrinsicGas`, `INTERNAL_ERROR: spammer`. Unmapped reasons (nonce too low, insufficient funds, intrinsic gas, gas limit, replacement-not-bumped, etc.) all appear as `INTERNAL_ERROR`. Note: message for a non-bumped replacement is `could not replace existing tx`, NOT geth's `replacement transaction underpriced`. DiscardReason strings: `txnprovider/txpool/txpoolcfg/txpoolcfg.go`.
- Txs submitted via RPC are marked local (`IsLocal=true` in grpc `Add`): exempt from min-fee-cap (`UnderPriced`) and per-account slot (`Spammer`) checks.

### Txpool rules (`txnprovider/txpool/pool.go`: `validateTx`, `validateBlobTxn`, `addLocked`; config `txpoolcfg/txpoolcfg.go` `DefaultConfig`)
- Three sub-pools: pending 10,000, baseFee 30,000, queued 30,000 (`--txpool.globalslots/globalbasefeeslots/globalqueue`). `--txpool.pricelimit` min fee cap 1 wei; `--txpool.accountslots` 16 txs/account (remote only); `--txpool.disable`, `--txpool.gossip.disable`, `--txpool.commit.every` 15s, `--txpool.queued.dormancy` 3h (evict queued senders with no on-chain activity), `--txpool.trace.senders`.
- Replacement: both tip cap AND fee cap must be >= old * (100+bump)/100; `--txpool.pricebump` default 10 (%); blob txs `--txpool.blobpricebump` default 100 (%) on blob fee cap (plus the regular tip/fee check); latent-overdraft rule: if new value > old value the tip threshold is multiplied by the sender's tx count. Cannot replace type-3 with non-type-3 (`can't replace blob-txn with a non-blob-txn`).
- Nonce gaps allowed (txs go to queued) up to `MaxNonceGap` 64 (`NonceTooDistant`; no CLI flag found) ; nonce < state nonce => `nonce too low`.
- Blob txs (type 3): need Cancun; no create; >=1 blob; blobs <= min(`MaxBlobsPerTxn`=6, per-block max for the fork); post-Osaka cell proofs must be `CellsPerExtBlob * nblobs` (wrapper_version 1); `--txpool.blobslots` 540 blobs/account; `--txpool.totalblobpoollimit` 5400 blobs total; blob fee cap below pending blob base fee not queued (`FeeTooLow`); KZG failure from a remote peer drops rest of that peer's batch.
- Set-code (type 4): need Prague; no create; non-empty authorization list; any account with delegated code (non-empty code hash) may have only ONE pending tx and it must be nonce == state nonce (`DelegatedTxnLimit`, `DelegatedNonceGap`); authority already reserved => `ErrAuthorityReserved`.
- Other limits: intrinsic gas incl. EIP-7623 floor (Prague) and Amsterdam repricings; tx gas <= block gas limit and <= EIP-7825 cap (`GasLimitTooHigh`); initcode size (EIP-3860/7954); tipCap > feeCap => `TipAboveFeeCap`.
- RIP-7560 account abstraction txs only if `AllowAA`.

### Batch / size / concurrency / subscriptions
- `--rpc.batch.limit` default 100: oversize batch => ONE error object `batch limit 100 exceeded (can increase by --rpc.batch.limit). Requested batch of size: N` (-32600) with the id of the first call, returned inside an array (`rpc/handler.go` `respondWithBatchTooLarge`). `--rpc.batch.concurrency` default 2 (batch calls execute with bounded parallelism); batches containing `eth_sendRawTransaction`, filter polling, admin peer methods, `debug_set*`, subscribe/unsubscribe, or any `engine_*` run sequentially in order (`inOrderMethods`). Empty batch => `empty batch`.
- Request body limit 32MB (`maxRequestContentLength`, `rpc/http.go`; WS message limit same). No hard response size cap; large responses are streamed (`jsonstream`; `--rpc.streaming.disable`). Ingress budget 256MB total (`rpc/ingress.go`).
- `--rpc.max.concurrency` default 0 = use `--db.read.concurrency`, -1 = unlimited; excess => -32005 overloaded / HTTP 503. `--ws.max.connections` 0 = unlimited. `--http.timeouts.{read,write,idle}` 30s/30m/120s (`rpccfg.DefaultHTTPTimeouts`).
- WS subscriptions: `--rpc.subscription.limit` default 1024 per connection (`subscription limit 1024 per connection exceeded (can increase by --rpc.subscription.limit)`, -32005). Kinds (eth_subscribe): newHeads, logs, newPendingTransactions (optional `fullTx` bool), newPendingTransactionsWithBody (Erigon ext), syncing (`eth_subscribe_syncing.go`), receipts (`TransactionReceipts`), plus `debug_executionWitnesses`-style witness subscription. Global filter/subscription limits `rpc.subscription.filters.*` (`rpc/rpchelper/config.go` `DefaultFiltersConfig`): maxlogs/maxheaders/maxtxs 10,000, maxsubscriptions 10,000 (`too many filters and subscriptions`, -32005), maxaddresses/maxtopics unlimited, timeout `DefaultFilterTimeout`. `--ws.api.subscribelogs.channelsize` 8192. Gzip: `--http.compression` default true, `--ws.compression` true, `--http.compression.loopback` false.
- Slow-request logging: `--rpc.slow` (0 off); `SlowLogBlackList` in `rpccfg.go`.

### eth_simulateV1 (`rpc/jsonrpc/eth_simulation.go`)
- Limits: 256 blocks per request, 5000 calls per block, 10,000 total calls (`clientLimitExceededError`, code -38026). Options: `traceTransfers`, `validation`, `returnFullTransactions`. Honors `--rpc.gascap`, `--rpc.returndata.limit`, `--rpc.evmtimeout`. Difficulty override after merge rejected. Validation errors mapped to the -38xxx codes via `txValidationError`.

### Tracing
- debug_traceTransaction/BlockByHash/BlockByNumber/Call (`debug_api.go`, `tracing.go`, `rpc/transactions` `TraceTx`). Tracers registered under `execution/tracing/tracers/`: native `callTracer`, `flatCallTracer`, `4byteTracer`, `prestateTracer`, `muxTracer`, `noopTracer` (`native/*.go`); JS tracers via goja (`tracers/js`); default (no tracer) = struct logger (`tracers/logger`). `TraceConfig` in `execution/tracing/tracers/config` (includes `Timeout`, `Reexec`). EVM timeout `--rpc.evmtimeout` applies. debug_ methods are streamed.
- trace_* (`trace_api.go`): `trace_filter` result cap `--trace.maxtraces` default 200; `--trace.compat` for bug-for-bug OpenEthereum. `--rpc.gethcompat` changes debug_storageRangeAt iteration order to geth's (sorted by keccak) — default off, so Erigon's order differs from geth.

### Prune modes (`db/kv/prune/storage_mode.go`, `db/config3/config3.go`, flags in `node/cli/flags.go`, docs `docs/site/docs/fundamentals/pruning-modes.md`)
- `--prune.mode` default `full`. full: blocks+state-history last 262,144 blocks (`DefaultPruneDistance`, EIP-8252 reorg window, ~36d); blocks: all blocks, history 262,144; minimal: 100,000 blocks (`MinimalPruneDistance`; deliberately not EIP-8252 compliant); archive: everything. Overrides: `--prune.distance`, `--prune.distance.blocks` (`keep-post-merge`, `keep-all`), `--prune.receipts.distance`, `--prune.include-receipts`, `--prune.include-commitment-history` + `--prune.commitment-history.distance` (needed for historical eth_getProof/witness without re-exec; default keeps none unless enabled). Mode is persisted in the DB; changing needs re-sync. `prune.DefaultMode` constant is ArchiveMode but CLI default is `full`.
- Pruned reads return the ErrPruned errors above (-32000), never empty results (except getBlockByNumber null for missing block).
- MaxGetProofRewindBlockCount in `httpcfg` bounds proof rewinds (flag name unverified); eth_getProof max 1024 storage keys (`maxGetProofKeys`).

## 5. Caplin (embedded CL)

- Code: `cl/` (agents.md at `cl/agents.md`, docs `docs/site/docs/fundamentals/caplin.md`). Run wiring `cmd/caplin/caplin1/run.go`; sentinel (libp2p) `cl/sentinel`, fork choice `cl/phase1/forkchoice`, EL bridge `cl/phase1/execution_client`, antiquary (history to snapshots) `cl/antiquary`, DAS/PeerDAS `cl/das`, validator duties `cl/validator`.
- Enabled by default only on networks where `clparams.EmbeddedSupported` (mainnet, sepolia, gnosis, chiado, hoodi, bloatnet); disable with `--externalcl` (`cmd/utils/flags.go`: `cfg.InternalCL = !externalcl`). When internal, Caplin talks to the EL in-process (not via authrpc) unless `--caplin.use-engine-api` (default false), in which case Beacon API is force-disabled. Checkpoint sync on by default (`--caplin.checkpoint-sync.disable`, `--caplin.checkpoint-sync-url`).
- Beacon API: router `cl/beacon/handler/handler.go` (`ApiHandler.init`, chi routes: `/eth/v1/{node,config,beacon,debug,events,validator,builder}`, `/eth/v2/...`, `/lighthouse/*`), per-endpoint handlers in `cl/beacon/handler/*.go`, response helpers `cl/beacon/beaconhttp/`, server start in `run.go` (`config.BeaconAPIRouter.Active`). Flags: `--beacon.api.addr` localhost, `--beacon.api.port` 5555, `--beacon.api.protocol` tcp, read/write/idle timeouts 5s / 31536000s / 25s, `--beacon.api.allow.origins/methods/credentials`.

Heavy Gloas/ePBS endpoints exist (execution_payload_envelope/bid, payload_attestations) — repo tracks upcoming forks aggressively.
- Standalone binary: `cmd/caplin` (own sentinel etc.), `cmd/capcli` (CLI tooling).

## 6. Quirks / deviations from execution-apis spec and other clients

- Default `--http.api` is just `eth,erigon,engine` — debug/trace/net/web3/txpool are all disabled out of the box; enabling `engine` there has no effect on the public port. `net_*`/`web3_*` method-not-found surprises on a default node.
- `ws.api` flag is a no-op; WS exposes the same namespaces as HTTP. WS is off unless `--ws`.
- eth_getLogs rejects ranges past the last EXECUTED block (not head) with -32602, and refuses very wide ranges (>1000 blocks) by default — geth/reth defaults differ. Result cap 20,000 logs.
- eth_call default gas = rpc.gascap (50M), not block gas limit; revert uses code 3 (matches geth); other EVM/state-transition errors in eth_call come back as -32000.
- Txpool rejection strings are prefixed `INTERNAL_ERROR:` / `FEE_TOO_LOW:` etc. and use Erigon's DiscardReason wording (`could not replace existing tx`, `existing txn with same hash`, `fork supporting this transaction type is not activated yet`); not geth's `replacement transaction underpriced`/`nonce too low` bare strings.
- eth_estimateGas can overshoot by up to ~1.5% (error-ratio shortcut); plain transfers return actual gas used.
- `pending` semantics differ per method (see tags); `eth_call` pending is an error.
- safe/finalized are forkchoice-driven: error -39001 (not -32000) when the CL has not provided them.
- eth_getBlockByNumber unknown => null, but state methods => error `block not found`.
- JWT failures are HTTP 403 text, not JSON-RPC; iat window 60s.
- Batches: oversize batch yields a single-element error array; engine_* calls in a batch are serialized.
- Extra non-standard APIs: erigon_*, ots_*, overlay_*, internal_*, eth_callMany, eth_getStorageValues, newPendingTransactionsWithBody, SSZ-REST Engine, MCP server, testing_ namespace.
- v3 data model: history before the prune window is gone by design; receipts/logs may be re-derived by re-execution when the receipt cache is off (slow but works within state-history window).
